# 关卡可解性判定：为什么写打手而不是调数据

## 零、结论先说

**第三关是可解的**，6 回合通关（上限 12）。之前"只能 2/3"不是关卡的问题，
是**手调配置 + 贪心打手**的能力上限。

而且这个结论不是靠继续调数据调出来的，是靠一个**会规划的打手**算出来的。
它同时给出了通关配置，我已把那套配置写回 `_test_levels.js` 当作正式用例。

## 一、问题出在哪一步

上一轮修完"装液必须落在基础标记"这条规则后，四关的成绩是：

| 关 | 手调配置的结果 | 上限 |
| --- | --- | --- |
| 一 | WIN@1 | 5 |
| 二 | WIN@2 | 8 |
| 三 | **2/3（打不完）** | 12 |
| 四 | WIN@11 | 16 |

第三关差一张单：需要**三只三角罐 + 一只长罐**，而罐位只有 6 个。

当时我写的判断是"这是没有证明可解，不是证明不可解"。要区分这两件事只有两条路：

1. 继续手调配置，直到某天打赢 —— 赢了也只能说"我找到了"，输了什么也说明不了；
2. 写一个比我更强的打手 —— 它赢了就**直接**证明可解。

我选了第二条。理由是第一条的失败信息量是零。

## 二、打手怎么工作（`_plan_levels.js`）

逐回合决定"用哪台 + 铺什么线"，三层：

**第一层：需求画像。** 扫未完成订单，数出还缺哪些形状、哪些液体。
接下来只考虑能产出这些形状/液体的产线，候选量立刻降一个数量级。

**第二层：领域启发式打分。** 对每个候选（主台 × 从台 × 0~2 条产线）打分：

- 这条产线产出的形状是缺口 ⇒ 加分（缺口越大加越多）
- 这条产线的形状**不是目标台的基础标记** ⇒ 扣 8 分（它根本产不进去）
- 这条液体被目标台**忌**（`ban`）⇒ 扣 8 分
- 有从台 ⇒ 加 0.5 分

这一层是**领域知识**，不是通用搜索。它便宜，而且在这个世界里几乎不会错。

**第三层：前 40 名真跑一回合。** 取启发式最高的 40 个候选，各深拷贝一份游戏状态，
真的跑一回合，用 `已完成订单×1000 + 总进度×10 + 罐位占用` 复核，取最优。

为什么先启发式再仿真：候选量级在千级（5 台 × 6 从台 × 数百种产线组合），
逐个真跑一回合太慢；而"这个台能不能产出这条需求要的东西"本身就是极强的信号，
用它筛到 40 个再仿真，成本降到可接受，而筛掉的基本都是注定浪费罐位的组合。

## 三、结果

```
L1 WIN@2 (上限 5)
L2 WIN@3 (上限 8)
L3 WIN@5 (上限 12)      ← 关键
L4 WIN@6 (上限 16)
ALL-WIN
```

第四关也从手调的 11 回合缩到 6 回合 —— 说明手调配置普遍偏保守。

第三关的获胜计划（`T<回合> 主台+从台 产线…`）：

```
T2 qinglong+xuanwu  j长,l酒,-       青龙产长罐灌酒 → 完成 #1
T3 qinglong+baihu   j三,j鼓→从,-    青龙产三角；鼓罐产到白虎（从台）
T4 qinglong+xuanwu  j三,l酒,-       青龙产三角灌酒 → 完成 #2
T5 baihu+xuanwu     j鼓,-,-         白虎产鼓罐 → 完成 #3
T6 （同 T5，收尾）
```

注意 T3 那一手：**同时**在青龙产三角罐、在白虎（从台）产鼓罐 —— 一台主台一台从台各干一份活。
这正是"主从台"存在的意义，也是手调配置一直没用上的一招（手调只把从台当临时仓库）。

这套配置已写进 `_test_levels.js` 的第三关用例（附注释说明它来自打手，不是手调），
现在稳定 `WIN@6 3/3`。

## 四、必须说清的边界

**打手输了不等于关卡不可解。** 它是启发式 + 40 名仿真复核，不是完备搜索：
启发式打分漏掉的候选永远进不了仿真。所以：

- 打手赢 ⇒ **可解性是确定的**（它交出了完整通关记录，可复核）；
- 打手输 ⇒ 只能说"在这个搜索预算里没找到"，要证明不可解得另做穷举。

这条不对称是有意的：我需要的是**正向证明**，而正向证明只要一条就够了。

## 五、对关卡设计的教训

1. **关卡的可解性必须由打手证明，不能由作者打赢证明。** 作者打赢只说明"存在一条作者会走的路"，
   而作者知道自己埋了什么，他的路不代表玩家能走。
2. **"手调配置打不过"最容易被我误读成"关卡太难"**，进而去削弱关卡 —— 那会毁掉关卡的意图。
   这次差一点就这么做了。
3. **打手顺便校准了上限。** 第四关上限 16 而打手 6 回合通关，说明上限给得太松；
   第三关上限 12 而打手 5 回合，同样偏松。上限应该按打手成绩乘一个余量定，而不是拍脑袋。
4. **从台的用法是一个尚未教学的机制。** 打手用"主台产甲、从台产乙"一招就解开了第三关，
   而现有四关里没有一关在教这件事。这是第五关的候选。


## 六、第五关：从台也是产线（新增）

### 关卡设计

三条 B 类订单，共 **8 只罐子**，跨两个形状家族：

| # | 需求 | 只能由谁产出 |
|---|---|---|
| 1 | 三角罐空 + 鼓罐空 | 三角：青龙/玄武 base；鼓：白虎 base |
| 2 | 长罐空 ×2 | 青龙 base（`j长` 每回合 2 只） |
| 3 | 扁罐空 + 扁罐:蜜 | 白虎 base + 白虎灌蜜（白虎忌酒，蜜可用） |

主台只有 **6 格**，全往主台产必然溢出，而溢出在原型里是**直接丢弃**（对应内核 `Warehouse` 的溢出丢弃计数）。
所以这关的解法必须用上从台的那 **4 格**与它自己的**液池**。

### 结果（`_plan_levels.js`，回合上限 5）

```
T2 baihu+qinglong j长→从,j扁,-
T3 baihu+xuanwu   j扁,j鼓,-
T4 baihu+qinglong j三→从,j扁,-
T5 xuanwu+baihu   j扁→从,l蜜,-
=> WIN@4 3/3   回合上限 5
```

上限按"打手成绩 + 1 回合余量"定（第 4 关给到 16 而打手 6 回合，是我上一轮记下的教训：
上限给太松，关卡就没有压力）。

### 一个必须记下来的缺口：原型里"换主台"是免费的

原本我想把这一关做成"**主台产甲、从台产乙，同时开工**"，但打手算出来的获胜计划是**逐段换台 + 部分产出打到从台**，
而不是两路真正并行。查了原因：

```js
// demo/puzzle_engine.js:440
function setBench(G, side, def) { ... }   // 只按新台容量夹一下液池，罐子全留着
```

**换主台在原型里不花任何代价**（不花回合、不丢罐子、不触发重组），
所以"逐段换台"永远不劣于"两台并行"，这一关就教不出并行。

而原系统里换台**不是免费**的：`SetMaster` 在旧台有资源时会走一次
`workshop_migration` 过程（两台快照 → 按禁令异同选 `SameBansCase`/`DifferentBansCase` →
改形 → `TransferAll`），过程占 tick、可失败、可取消。**原型与内核在这里有语义差**，
与之前那处"原型比内核宽松"（灌液漏了基础标记）是同一类问题，只是这次方向相反：原型比内核**便宜**。

要让"两台同时开工"成为必修课，得先给原型的换台加代价（占一回合、或按原系统那套重组规则处理旧台的罐子）。
那会改动第三、四关的可解性，需要打手重跑全部关卡 —— 记为原型线的待办，不在本轮做。
