# 退役说明：这套 JS 原型不再定义任何规则

这里放的是离线原型（`puzzle_engine.js` / `battle_engine.js` 及其 UI、数据、自检脚本）。
它现在只有一个用途：**历史留档**。请不要再从这里读"游戏该怎么算"。

## 为什么退役

原型是一套用 JavaScript 复刻的规则实现，内核（`src/JarSystem.Core`）是另一套。
两套实现并存时，每一次都栽在同一件事上：

| 现象 | 根因 |
|---|---|
| 原型里"移动罐子到从台"这种解法永远搜不到 | `grow()` 只生成 5 种操作，从不生成"搬罐"步骤 |
| B 类订单明明有解却判不可行 | 液体池按"主台 + 从台"算术相加，罐子却按所在台判规则 |
| 评估完就动手 | `runTurnRaw` 在同一遍循环里"想"和"做" |
| 换台不花钱 | 搬运动作在原型里不存在 |
| 战斗是第二套规则 | `battle_engine.js` 不与内核共享任何判定 |

结论：一个世界、一套规则、一条时间线。规则只住内核，界面只做表达。

## 现在的入口

| 想做的事 | 去哪 |
|---|---|
| 玩/看内核跑起来的世界 | `run.bat`（默认第一关），或 `dotnet run --project src\JarSystem.Web -- --level N` |
| 看内核怎么说 | `http://127.0.0.1:5289/world.html`（世界状态 / 帧时间线 / 不变量 / 命令面板） |
| 改关卡内容 | `config/levels/*.json`（世界 + 提示 + 回合上限 + 目标单数） |
| 查"这一关能不能赢" | `test/JarSystem.Tests/LevelWinnabilityTests.cs`（基线打手把每种主从台摆法都打一遍） |
| 网页冒烟 | `node tools/web_smoke.js http://127.0.0.1:5299`（真点按钮） |

## 这里的文件还能跑吗

能，但要自己在 `demo/_退役/` 里执行，例如 `node _test_engine.js`。它们现在读的是本目录里的
`puzzle_data.js` / `battle_data.js`，与内核无关；**跑通不代表内核会算出同样的结果**。
判断行为请以内核测试和 `world.html` 为准。

## 历史报告留在 `demo/`

`demo/` 下的一批 `.md`（规则草案 v0.1–v0.4、第 2–11 步设计、可解性判定、平衡实验等）
是这套原型的推导记录，仍然有用——它们记录了玩法是怎么被想清楚的，但不再是规范。
现行规范的入口是 `规则.txt` 与 `CONSTRAINTS.md`。
