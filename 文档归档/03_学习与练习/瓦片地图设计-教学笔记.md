# 瓦片地图：格点、线性变换与自动衔接 —— 机制式教学

先给一条主线，之后所有推导都可以挂在它上面：

**瓦片地图的全部运转 = 三个动作的循环：**

1. **离散化**：把连续的世界切成格子，每个格子只存一个"内容标签"（索引）。
2. **铺放**：用一组基向量把格点坐标线性映射到屏幕像素。
3. **衔接**：用"邻域规则"自动决定每个格子该画哪个瓦片变体，让相邻瓦片咬合无缝。

---

## 一、TileMap 与 TileMapLayer：容器与画布

**它是怎么运转的（机制）：**

Godot 4 起（4.0 官方拆分了这两个职责）：

- **TileSet**：一个纯资源，不进场景树。它是"瓦片字典"——一张大图（图集）+ 每块瓦片的定义：贴哪个图、碰撞形状、地形 peering 位、动画帧。它回答"世界上存在哪些图块"。
- **TileMapLayer**：一个场景节点，持有"索引网格"。它**引用**一个 TileSet，并保存自己的 cell 数据——"第 (3,7) 格放了字典里的第 12 号瓦片"。渲染时它遍历自己的格子，把字典里的图形贴到对应格点。它回答"这些图块摆在哪里"。
- **TileMap**：只做容器。它自己不放瓦片，把若干个 TileMapLayer 作为子节点**叠**起来渲染。

**为什么会这样分（推导）：**

一个格子只能存一个索引，即一格只有一个语义。但世界的一处地面往往同时是"草地 + 草上一朵花 + 花下有碰撞"。一格装不下三种语义 → 于是引入**层**：地面材质一层、花草装饰一层、碰撞/导航各自独立记录。层 = 语义轴的分离，相当于画家用多张透明胶片叠出同一幅画。所以：

> TileMap : TileMapLayer = 相册 : 胶片页；TileSet = 贴纸册；地图 = 索引表。

## 二、等距视角与"Y 减半"：这是一次线性映射

**机制：** 引擎渲染任意瓦片地图时，对每个格子 (i, j) 只做一件事：

```
屏幕位置 = 原点 + i·u + j·v
```

u、v 是两根"格子基向量"。把 u、v 写成矩阵 M 的两列，格点→屏幕就是一个**线性映射** M：

- 方形网格：u = (W, 0)，v = (0, H)，M 是单位阵的缩放。
- 等距菱形：u = (W/2, H/2)，v = (−W/2, H/2)。Godot 里 tile_size = (64, 32)，即 H = W/2 —— 这就是你看到的"Y 减半"。

**推导链（可以自己验算每一步）：**

1. 45° 旋转的矩阵 R = [[c, −s], [s, c]]，其中 c = s = √2/2。
2. "Y 轴减半" = 左乘 diag(1, 1/2) —— 沿纵轴的**非均匀缩放**。
3. 于是等距映射 M = R · diag(1, 1/2) · (一个整体缩放系数)。等距 = **旋转 + 各向异性缩放**。
4. 反向操作：鼠标拾取（点到哪个格子）= 对 M 求**逆矩阵**，把屏幕坐标变回格点坐标。
5. det(M) = 一个格子占据的屏幕面积（行列式的几何意义）——决定像素密度、遮挡关系。
6. 术语修正：剪切（shear）是 det = 1 且特征值全为 1 的形变；"Y 减半"是各向异性缩放。两者同属仿射变形家族，能联想到一起很正常——它们都能把正方形格扭曲成菱形格。

**为什么恰好是 1/2 而不是别的数（推导）：**

真等距投影的视角是 30°，其边界线斜率 tan30° = 1/√3 ≈ 0.577，是**无理数**——像素阶梯永远对不齐，必然出现锯齿与接缝。2:1 的斜率是 0.5：横向每走 2 像素、纵向走 1 像素，是完美的整数阶梯。所以"Y 减半"不是美术的随机选择，而是**像素网格的可除性约束**对无理数的妥协。

**线性代数在瓦片系统中的完整角色清单：**

| 瓦片概念 | 线性代数对应 |
|---|---|
| 网格类型（正方/等距/半错位/六边形） | 基向量的选择（六边形 = 带斜边的基） |
| 渲染 | 格点 → 屏幕的线性映射 |
| 鼠标拾取、格点↔世界坐标互转 | 逆映射 |
| 图集中的每块瓦片 | 纹理空间中的一个平移（UV 偏移） |
| 一格占多大屏幕面积 | 行列式 |
| "16 种配置只剩 6 种" | 旋转群作用下的轨道计数 |

## 三、瓦片设计史：从 256 种组合到 6 块角瓦片

按"被什么问题逼出来的"顺序，每个阶段先讲机制：

### 阶段 1：硬件瓦片（约 1983 年，NES）
NES 的图像处理器（PPU）里**没有帧缓冲**。画面是硬件实时"查表"画出来的：图案表存 8×8 瓦片的像素，命名表（nametable）存 32×30 的瓦片索引。也就是说——**"瓦片地图"最早不是软件概念，而是硬件的内存布局**：整帧画面 = 查两次表。为什么 8×8：一帧全彩帧缓冲要 32KB 内存，而 NES 整机只有 2KB 显存。是内存价格逼出了瓦片。
（SNES 增加了多层背景、每瓦片 16 色；Mode 7 更是把"仿射变换"做进硬件——每扫描线执行一次缩放/旋转的线性映射。线性代数直接变成了硅片。）

### 阶段 2：元瓦片与 RLE（压缩）
8×8 太小，画不出完整内容 → 艺术家把 2×2（16×16）或 4×4 拼成**元瓦片**（metatile），关卡数据只存元瓦片索引。《超级马力欧》的关卡 = 16×16 元瓦片 + RLE 编码（"连续 N 个同样的块"只记一次）。机制：**分级表示 + 行程编码**——"一个地图需要很多瓦片"的问题第一次被压缩算法解决。

### 阶段 3：软件渲染、大瓦片、图集
PC 时代瓦片长到 16–64 像素；几十上百个瓦片打包进**一张图集纹理**，整张地图一次绘制调用画完。机制：GPU 切换纹理昂贵 → 所有瓦片放一张图 = 一次绑定。每块瓦片 = 图集里的一个 UV 矩形。

### 阶段 4：位掩码自动过渡（autotiling）——问题正式爆发并第一次被解决
**问题机制**：草地与水的交界线有各种走向：直边、外角、内角、斜角。每种走向需要一块专门画的过渡瓦片。只看一个格子的 3×3 邻域就有 2^8 = 256 种配置——每种都手绘是灾难。

**解法机制**：给 8 个邻格各分配一个二进制位：
上左=1，上=2，上右=4，左=8，右=16，下左=32，下=64，下右=128。
引擎读取邻域 → 加出一个 0–255 的**位掩码** → 查表选出瓦片。只画有意义的变体：**47 块**（含内角，覆盖全部 256 种配置，旋转/镜像等价合并；Godot 4 的"角+边匹配"模式）或 **16 块**（只看 4 邻、无内角——RPG Maker 的 A 瓦片就是这套）。

**数学血统（重点）**：1961 年数学家王浩研究过完全同一件事——**王浩瓦片**：瓦片边上有颜色，两块瓦片能相邻 ⟺ 共享边颜色一致；"给定一组瓦片能否铺满整个平面"（多米诺问题）被证明**不可判定**（Berger，1966，还由此发现了非周期铺砖）。位掩码就是"边色"的低配版。2003 年 SIGGRAPH 还用它做纹理合成。你用的自动过渡，是 60 年前的数学成果在游戏里的落地。

### 阶段 5：地形集（Godot 4 / Tiled）
把"材质"提升为第一公民：草地、水、沙各是一种**地形**；每块瓦片记录"我的哪些边/角要求邻格是同种地形"（peering 位）；你**只涂材质**，引擎自动为整个区域解析过渡。匹配模式"角+边 / 只角 / 只边"分别对应 47 块 / 角分类 / 16 块。机制：画地图从"选瓦片"变成"填材质"，过渡由**约束系统自动求解**。

### 阶段 6：双网格系统（约 2019–2021；Oskar Stålberg 提出，Jess Hammer 实现 Unity 与 Godot 版）
机制分三步：
1. 你在**粗网格**上只画材质（每个粗格对应 2×2 个细格）；
2. 渲染发生在 2 倍分辨率的**细网格**上，过渡瓦片画在粗格的**四个角**上（"角瓦片"）；
3. 每块角瓦片由它周围 **4 个**粗格的有无决定：2^4 = **16 种配置**；按旋转对称合并后只剩 **6 种**（加实心/空白 2 种）。

于是：47 块 → 16 块 → 6 块；检查 8 个邻居 → 只检查 4 个；还能画**圆角**（边界弧线藏在 2×2 内部）；玩家看到的材质轮廓与粗网格对齐，不歧义。

**数学本质**：细网格 = 粗网格的**对偶格**（格子 ↔ 顶点互换）。在对偶格上按顶点周围 4 格分类选瓦片，就是**行进方块算法**（Marching Squares——1987 年行进立方体的二维版）：按方格的 4 个角点状态把等值线分成 16 种走法并查表。双网格 = **图论对偶性 + 等值线提取**合体。

### 阶段 7：相邻发展——WFC（波函数坍缩，Maxim Gumin 2016）
给瓦片定义"谁能和谁挨着"的邻接规则，算法用约束传播自动生成整张合法地图（《Bad North》《Townscaper》等）。方向从"减少过渡瓦片"转向"让规则自己生成世界"。

**回答"是否涉及数学"**：全程都是。组合学（256→47/16 与 16→6 是旋转群的轨道计数）、图论（对偶格、邻接图）、数值几何（行进方块）、线性代数（基、映射、行列式）、约束求解（WFC）、信息论（RLE、元瓦片）。

## 四、一座山不可能只有一个瓦片集

**机制回答**：一格 = 一个索引 = 一个语义，而山需要许多正交的语义轴：

1. **材质轴**：草地、土、岩、沙、水——放进同一个 TileSet 的**地形集**里。它们互相接触 → 每对材质一条边界 → 各自需要一套过渡瓦片（47/16 块）。**k 种材质 → k(k−1)/2 条边界**，这才是瓦片数量的真正来源。
2. **覆盖轴**：花、草丛、石子是"装饰"，放在另一个 TileMapLayer（y-sort 或随机散布 scatter），不参与地形过渡，是独立的小瓦片（做十几个变体防重复感）。
3. **行为轴**：水要动画（一块逻辑瓦片 = 多帧图片），树要按脚点排序（y-sort），岩壁要碰撞——不同行为 = 不同瓦片/层。

**推导练习**：为什么花必须和草分开？若把花画在草地瓦片上，则"每块草地 × 每朵花"的组合全部要画出来（乘法爆炸）；分开后是"草 + 花"（加法）。**分层在信息论上的意义：把组合爆炸变回求和。**

## 五、画师面对一幅自然风景时的思路

按真实发生顺序描述这个心理过程：

1. **找周期**：盯着画面问"什么在重复"——草丛的团簇、石头的分布、土粒的纹理。瓦片的前提是**周期性**；画师的眼睛是一台"基频探测器"。
2. **拆层（频率分离）**：低频 = 地面底色与材质斑块（决定地形集）；高频 = 花草点缀（决定散点装饰层，稀疏放置以躲避视觉重复）；竖直维度 = 树、悬崖（决定 y-sort 层）；水 = 时间维度（动画帧）。
3. **网格意识**：每块瓦片都活在一个**环面**上——上边接下边、左边接右边（周期性边界条件）。于是：光照方向必须全局一致；任何一块瓦片内部"独一无二"的特征都会在平铺中变成显眼的重复 → 特征要压低对比度或做多块变体轮换。
4. **过渡思维**：画师不画"场景"，画"边界形状的字典"——草地与水之间那条曲线的每一种走法：直边、外角、内角、斜切。他会先问："引擎按 8 邻域还是 4 邻域分类？按边还是按角？"——这直接决定他画 47、16 还是 6 块。**网格系统 = 边界曲线的数字化方案**（直线之于像素是 Bresenham 算法，边界之于网格就是过渡瓦片字典）。
5. **网格换代如何改变他的思路**：
   - 47 块时代：画师逐格穷举 3×3 组合，易漏内角（最常见的 bug）；
   - 地形集时代：只画一次边界字典，引擎负责解析组合——画师从"拼图工"变成"字典编纂者"；
   - 双网格时代：只画 6 块角瓦片 + 2 块实心，还能上圆角——画师提供**生成元**，引擎张成所有组合（线性代数里的"基"与"张成空间"）；
   - WFC 时代：画师给邻接规则，引擎自动生成世界——画师变成"语法设计者"。

   **网格升级换代 = 把穷举组合的劳动从人转移给算法**；画师的思考从"每一个具体画面"升维到"生成所有画面的规则"。

## 六、网格如何描绘世界，瓦片为什么被放在一起

**机制链条**：

1. **网格 = 对世界的采样**。像素把颜色离散化；瓦片把"空间 + 内容"离散化。一张地图就是一个函数 f：格点集合 → 瓦片集合。一片连续草地被量化为"这些格子的标签都是草地"。
2. **相邻性 = 约束系统**。两块瓦片能放在一起 ⟺ 共享边一致：边上的像素是两块**共有**的函数值。这正是王浩的"边色匹配"。引擎的位掩码 / peering / 双网格规则，都是在维护这个约束：给一个邻域配置，规则函数选出**唯一**一块满足约束的瓦片。
3. **三个层次的原因**（为什么放在一起）：① 视觉连续性——边咬合、无接缝；② 语义规则——可走 / 碰撞 / 水域；③ 自动解析——规则函数把"材质涂鸦"展开成无缝地图。
4. **连续感是被重建的**：网格 + 局部基元 + 邻接一致性 = 离散化后的连续世界。正如有限差分/有限元在格点上用局部基函数重建场，瓦片地图用局部瓦片重建风景。
5. **推导练习**：为什么规则函数必须"每个邻域恰好一个瓦片"？若两种瓦片竞争同一配置 → 地图状态不确定（函数退化成关系）；若某配置没有瓦片 → 地图出现洞（函数未定义）。**好的瓦片系统 = 处处有定义且唯一的规则函数。**

## 收尾：一条线串起全部

瓦片地图 = 三层数学的叠加：

- **空间层**：格点 = 整数格；网格类型 = 基的选择；渲染/拾取 = 线性映射及其逆。
- **内容层**：瓦片 = 字典；地图 = 索引格；分层 = 语义正交分解。
- **规则层**：邻接约束 = 合法拼接的定义；autotiling / 对偶格 / WFC = 自动满足约束的算法。

你的"Y 减半"直觉落在空间层，双网格的 16→6 落在规则层，山地的多集拆分落在内容层——它们本来就是同一台机器的三个零件。
