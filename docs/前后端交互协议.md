# 前后端交互协议

> 日期：2026-11-03
> 范围：`play.html` / `world.html`、WebSocket 命令、HTTP 查询、状态与表现帧。

## 1. 第一原则

前端负责**本地交互与表现**；后端负责**世界事实、规则、时间和审计**。

决定是否发送 JSON 命令，只问一个问题：

> 这个选择是否会改变可回放的世界，或需要读取只有内核才知道的事实？

- 否：留在前端本地状态。
- 是：发送明确命令或查询。

页面不能为了动画、选择器展开、折叠、高亮而创建“伪命令”。

## 2. 交互分类

| 类别 | 是否发后端 | 例子 | 权威来源 |
|---|---|---|---|
| 纯表现状态 | 否 | 打开/关闭选择器、悬停、卡片高亮、Tab、日志折叠、日志筛选、动画播放 | 页面 |
| 输入草稿 | 否 | 尚未确认的速率选择、待提交的订单需求编辑 | 页面 |
| 查询 | 是 | `getState`、`getSteps`、`/api/levels`、`/api/invariants` | 内核/宿主 |
| 世界命令 | 是 | 推进时间、主从台、产线速率、容量、订单、关卡 | 内核 |
| 过程命令 | 是 | `startOrder`、`cancelProcess`、场景/修饰器操作 | 过程系统 |
| 推送事件 | 后端→前端 | `state`、`world`、`frame`、`steps` | 内核 |

### 2.1 当前纯本地动作

- `levels`：只打开关卡选择器；选中关卡后才发 `loadLevel`。
- `pickmaster` / `pickslave` / `closepicker`：只控制选择器。
- `logfilter`：只过滤已收到的日志。
- 点击日志行折叠/展开。
- 动画、toast、焦点、选择态、悬停态。

这些动作不得发送 WebSocket 消息。

### 2.2 需要发送命令的动作

- `advance` → `manualTick`：世界时间和回合预算改变。
- `setmaster` / `setslave`：主从位置改变。
- `rate` / `lrate`：生产配置改变。
- `check`：可行性结果是内核事实，且可能进入命令日志。
- `start` / `execute` / `cancel`：过程生命周期改变。
- `del` / `up` / `down` / `neworder`：订单内容或执行顺序改变。
- `restart` / `gotolevel`：世界生命周期改变。

## 3. WebSocket 信封

当前 v1 请求：

```json
{
  "type": "updateProducerRate",
  "data": {
    "producerName": "陶工甲",
    "shape":  "圆罐",
    "rate": 0.4
  }
}
```

当前 v1 回包/事件：

```json
{
  "type": "state",
  "data": {}
}
```

约束：

1. `type` 必填且来自生成的 `CommandName` / `MessageType` 联合。
2. `data` 必须是对象；命令字段来自 `CommandPayloadMap`。
3. 未知命令返回 `error`，连接不得因单个坏消息断开。
4. 命令和回包键名由契约生成物约束，前端不得手拼未声明字段。
5. 后端可以新增可选响应字段；删除/改义必须走契约迁移。

### 3.1 后续兼容扩展

富交互需要并发请求上下文时，增加可选字段：

```json
{
  "requestId": "client-42",
  "type": "startOrder",
  "data": { "orderId": 7 }
}
```

直接回包应回显 `requestId`；广播 `state`/`frame` 不伪造单个请求归属。该字段是后续增量，
不能改变旧客户端无需 `requestId` 的兼容性。

## 4. 错误协议

所有可预期拒绝统一为：

```json
{
  "type": "error",
  "data": {
    "message": "从台必须是空的临时工具位"
  }
}
```

规则：

- 前端显示内核返回的原文，不改写成“成功”或静默吞掉。
- 错误不得只写 console；必须有可见反馈。
- 世界命令失败后，前端重新读取权威 `state`，撤销任何乐观视觉状态。
- 非法 JSON/字段类型只影响当前命令，不应断开整个连接。

## 5. 乐观更新与实时表现

### 允许

- 点击按钮后立即显示“提交中/选中”。
- 播放纯装饰动画。
- 在已知 `frame` 后请求 `state`。
- 本地合并高频重绘。

### 禁止

- 在后端确认前本地增删罐子/液体。
- 用动画承诺尚未发生的交付、订单成功或关卡胜利。
- 页面自行计算“能否执行”或价格。
- 进度条自行超越内核 `state` / `processes`。

`state` 是权威；`frame` 只是“可能变了”的失效通知；动画必须能丢弃且不改变数据。

## 6. 重试与幂等

当前连接模型由宿主串行 Gate 保证单世界互斥，但没有通用请求幂等键。

因此：

- 断线后不得自动重放状态改变命令。
- 重连必须先 `getState`，再按最新世界重新决定。
- `getState` / `getSteps` 可安全重试。
- `manualTick`、`startOrder`、`moveOrder`、生产速率、切换等不得盲目自动重试。
- 若未来加入自动重试，必须先增加稳定 `requestId`/幂等键和回包关联。

## 7. 协议变更流程

新增或修改交互时必须同步：

1. `CommandDispatcher` 的命令分支与严格参数校验。
2. `contract.d.ts` 的 `CommandName` 与 `CommandPayloadMap`。
3. 协议守卫和聚焦测试。
4. 状态变化时的权威 `state` 广播。
5. 页面本地动作 / 后端命令分类文档。
6. 涉及持久状态时，执行完整 `VERDICT=OK` + `QUALITY-OK` 门禁。

## 8. 设计检查表

- [ ] 这个操作只是 UI 状态吗？如果是，没有网络调用。
- [ ] 这个操作改变世界吗？如果是，发送类型化命令。
- [ ] 后端拒绝时，用户能看见原因吗？
- [ ] 动画是否只消费事实，而不是制造事实？
- [ ] 重连是否先同步状态，而不是重放旧意图？
- [ ] 新增字段是否先进入契约，再进入页面？
- [ ] 是否避免让页面成为第二个规则引擎？
