# 工作台写入主体清单（审计于 2026-11）

> 回答一个问题：**现在到底有哪些主体能改真实工作台，有没有一条路径绕开了端口。**
> 结论：**没有绕开**。所有写入都经 `Domain/Workshop.cs` 的端口方法，且 `Domain/Jar.cs` 的
> 变更方法全是 `internal` —— 端口是唯一的门。这个结论现在由
> `test/JarSystem.Tests/WorkshopWritersTests` 机器检查（四条），不再依赖任何人的记忆。

## 一、三个角色（不是"执行器一个主体"）

| 角色 | 碰真实工作台吗 | 说明 |
|---|---|---|
| **求解器**（`src/JarSystem.Core/Solver/`） | **不碰** | 输入是 `WorkshopInfo` / `JarState`（纯值），输出是 `SolverStep` 列表。机器门：`SolverNeverTouchesARealWorkshop` |
| **执行器**（`src/JarSystem.Core/Executor/`） | 碰 | 按计划或贪心把步骤施加到真 `Workshop`，并且**校验返回值** |
| 其它主体（命令 / 迁徙 / 回流 / 仓库流入 / 过程执行） | 碰 | 与执行器共用同一组端口 |

## 二、九条写入路径（全部经端口）

| 主体 | 文件 | 做什么 |
|---|---|---|
| 玩家手工命令 | `Commands/JarCommands.cs` | 灌注 / 倒出 / 改形 / 转移，逐个检查 `(bool, reason)` |
| 执行器（计划） | `Executor/SolverStepApplier.cs` | 把 `SolverStepDto` 逐条施加 |
| 执行器（兜底） | `Executor/GreedyPlanBuilder.cs` | 求解器未判定时的贪心 |
| 订单交付 | `Orders/OrderEvent.cs` | 从交付台取下交付罐 |
| 失败/结束回流 | `Orders/SlaveRollback.cs` | **唯一**会被回滚的东西 |
| 换台搬运 | `Orders/Switching/ResourceTransferrer.cs` | 旧台 → 新台 |
| 换台重组 | `Orders/Switching/SwitchCases.cs` | 游离液体灌进旧台基础形状的空罐 |
| 过程化执行 | `Process/Execution/OrderExecutionSession.cs` | 异步轨，同一套端口 |
| 仓库流入 | `Production/Warehouse.cs` | 「中央仓库单向流动」的唯一出口 |

## 三、机器门守的四件事

1. `SolverNeverTouchesARealWorkshop` —— 求解器目录零端口调用（"只算不做"的边界）。
2. `EveryWorkshopWriterIsOnTheList` —— 出现未登记的写入文件就红，逼作者当场回答"它凭什么能改世界"。
3. `TheListHasNoStaleEntries` —— 登记了却不再写入的文件必须删掉（噪音清单等于没有清单）。
4. `JarMutationStaysInternalSoThePortRemainsTheOnlyDoor` —— `Mark/Unmark/PourIn/ClearLiquid/RestoreLiquid/Reshape` 一旦变 `public`，就能绕过端口直接改罐子。

负向验证：把 `Production/Warehouse.cs` 的登记改名 ⇒ 两条测试同时变红（未登记 + 陈旧登记），还原后绿。

## 四、这道门自己踩过的坑（记下来，因为它是文本扫描）

第一版用 `\.(Ports)\(` 直接扫，红了三处**假阳性**：
`st.AddLiquid(...)`（`SolverState` 的方法）、`WorkshopOperation.PourOut()`（枚举工厂）、
`list.Add(...)` 同族。修法是加一个**接收者白名单**（只放纯值/工厂，不放任何工作台变量）。

这不是漂亮的解法：精确做法是用 Roslyn 分析器按**类型**判定。在此之前，
白名单必须保持"只放纯值局部变量与工厂类型"这条纪律，否则门会慢慢失效。
