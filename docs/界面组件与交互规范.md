# 界面组件与交互规范（play.html）

这一页是**内核的表达器**：内核说事实，页面只负责"把它说成人话、摆成人看得懂的形状"。
本文是这张页面的组件清单与交互约定，改名/增删组件时同步改这里。

跨前端的命令、查询、错误、重试与实时同步规则见
[前后端交互协议](前后端交互协议.md)；本文只描述 `play.html` 的具体组件。

## 一、四层，不许串层

| 层 | 在哪 | 允许做什么 | 禁止做什么 |
|---|---|---|---|
| 内核事实 | `src/JarSystem.Core` | 判定、执行、记账、过程日志 | 不认识"页面""按钮""中文措辞" |
| 投影（服务端） | `src/JarSystem.Web/CommandDispatcher.cs`、`StateSerializer.cs` | 把事实**原样**装进 DTO/回包 | 不做判断、不补字段、不排序以外的事 |
| 视图模型（页面） | `wwwroot/js/play.js` 的措辞函数 | 把英文动作名换成中文、按状态选样式 | 不做规则判断（"能不能做"只能问内核） |
| 组件（页面） | `play.html` + `play.css` | 摆形状、给反馈 | 不自己算进度、不自己判胜 |

判别口诀：**页面里出现 `if (资源够不够)` 就是串层**。资源够不够由 `feasibilityResult` 说，
页面只问"内核说能不能"，把 `feasible` / `blockage` 原样画出来。

## 三、交互约定（改页面之前先读）

1. **世界不会自己走**：只有 `manualTick` 推进时间；派单、分析、改速率、换台都不推时间。
2. **开始之前必须"现在就能做"**：`feasible` 为假时「开始」不可用，并显示内核给的 `blockage`。
   点在赌，赌输要付代价（过程会失败），玩家会以为页面坏了。
3. **每个动作都要有可见后果**：发命令后立刻有本地记录条目，随后由内核回包/帧把状态改正。
4. **禁用必须说出理由**：按钮 `title` 与卡片说明同时给出（"还做不了：先在进度条上看缺什么"）。
5. **数字只有内核一个来源**：回合、进度、步数、产能、库存都来自 `state`，页面不推算。
6. **措辞集中一张表**：`OP_ZH`（`play.js`）是唯一动词表，新增动作只加一行。
7. **失败是代价，不是 bug**：过程失败会在记录里显示"失败：委托 #N（原因）"，不要静默吞掉。
8. **结束态锁住推进**：赢/输/回合用尽都禁用推进，主按钮文案改成"本关通过 / 本关结束"。
9. **帧只说"变了"**：`frame` 到达时页面向内核再要一次 `getState`（节流 120ms），不自己推断增量。
10. **动画只反映数值变化**：入库方片闪一下靠"前后两次数量比较"，不做假动画。
11. **日志拉取节流必须保留尾随请求**：过程完成与上一条进度帧可能同 tick 到达，不能丢掉 `succeeded`。
12. **重开/换关必须清空整份页面世界缓存**：包括 `logs`、`stepSeen`、`subjectBy`、`feas`、节流计时器；
    内核重开会把 journal seq 重置到 1，旧去重集合会让新日志永久不可见。
13. **每次手动推进都有可见反馈**：至少记录推进后的回合、仓库净存量，以及活动订单当前步和剩余刻数。
14. **订单终态必须主动提示**：`success`/`failed` 和关卡 `won`/`lost` 同时产生 toast 与持久日志，不只改按钮文字。
15. **直接交付不占 tick**：开始订单时资源已经满足形状与交付位置 ⇒ 命令返回时订单即完成；
    页面必须立即显示完成 toast，不能先画一个假的“执行中”再等回合。
16. **B 类迁移是一个步骤**：页面把“全部必要罐子和液体到从台”显示为一个迁移单位；
    迁移完成后若已满足交付，不再额外显示 MATCH 步骤。
17. **世界回合与订单步骤**：每次手动推进完成一个完整世界回合，并默认推进一个订单实现单位。
    `ticksUntilNextUnit` 在有显式减速/阻断时仍会大于 1；日志必须写“世界推进到第 N 刻”，
    不能写成“订单消耗了第 N 回合”。
18. **下一步倒计时与时限分离**：`ticksUntilNextUnit` 表示距下一执行单位，
    `remainingTicks` 表示距 deadline；两者不能混用。
19. **做法必须标明执行者**：每个耗时步骤显示“主台/迁移/从台 + 工作台名”，
    罐子使用稳定 Id 和当前形状；直接匹配单独标为“不耗时预留”。

## 四、消息 ↔ 组件对照

| 消息 | 触发 | 落在哪个组件 |
|---|---|---|
| `state` | 连接、任何命令回包、`getState` | 全页（`render()`） |
| `allFeasibilityResults` / `autoCheckResults` | `checkAllFeasibility`、宿主定时检查 | 订单卡进度条与说明 |
| `feasibilityResult` | `checkFeasibility` | 单张订单卡 |
| `steps` | `getSteps` | 记录栏 + 订单卡"正在做" |
| `frame` | 内核每次世界/过程变化 | 触发重取 `state`、缓存 `subject` 后拉 `steps` |
| `error` | 命令被拒 | toast（原文照转） |

## 五、为什么没有前端框架

`verify.bat` 的 JS 门只有 `node --check`，仓库刻意**没有构建链**：Vue/Element 要么走 CDN（离线不可用），
要么引入打包器与依赖目录（推翻整套门禁契约）。缺的从来不是框架，而是**组件层与状态投影**：
把 `getState` 投影成"谁、在做什么、第几步"，并让帧驱动刷新 —— 这两件事手写足够。

## 六、已知欠账

- 记录栏只有一屏（`MAX_LOG = 200`），没有按订单筛选/折叠。
- 进度条语义是"以当前资源这一单能走到哪一步"，不是"执行到哪一步"；执行进度另有一段 `.oexec`。
- 移动端未实测；触控下选择器层级可能有遮挡。
- 关卡切换仍需重启宿主（`--level N`），页面只给提示。

## 补记：换关、记录筛选、设计 token（S1 打磨第二轮）

用户要求「不用管移动端，但四件事都要解决」，四件都落在这里：

| 之前 | 现在 | 落点 |
|---|---|---|
| 换关要重启宿主（`run.bat --level N`） | 页面内换关：`关卡选择` → 点某关 | 命令 `loadLevel {index}`；宿主 `JarSystemService.LoadLevel` |
| 记录栏只有 200 条一屏、不能筛 | 记录栏带筛选条：全部 / 只看执行 / 每一张委托；点一行可折起 | `play.js` 的 `logFilter`、`folded`、`renderLogbar` |
| 只有"入库闪一下" | 推进时把少掉的罐子从**中央仓库飞到主台**（ghost 元素，只画位移不改数据） | `play.js` 的 `captureStageJars` / `runFlowAnimation` |
| 间距/字号/圆角是每处各写一份像素 | 全部走设计 token | `play.css` 的 `--sp-*`/`--fs-*`/`--r-*`/`--dur*` |

**换关为什么能做在宿主层**：核心不认识"关卡"，一关只是"打包好的一份 `WorldOptions` + 提示 + 回合上限"。
换关 = 丢掉旧世界、按关卡的 world 起一局新的、再按模板派单、按信封摆台。
所有消费者（命令、HTTP 端点、两个后台服务）都用 `svc.System` **现取**，因此替换实例后不必逐个重新接线；
并发由 `svc.Gate`（`SemaphoreSlim(1,1)`，命令分派器每条命令先 `WaitAsync`）保证。

**注意事项**：换关后 `PresentationFeed` 的 `seq` 从 0 重新计数，页面必须把属于上一局的缓存整批丢掉
（`logs` / `stepSeen` / `subjectBy` / `feas`），否则会画出"上一关的订单还挂着"的假象。
**重开本关同样会重置过程日志序号**，因此和换关共用同一个 `clearWorldCaches()`；只清空 `logs`
而保留 `stepSeen` 会把新一局的全部 `step_applied` / `succeeded` 当成重复项丢弃。
换关的回包里已经带了新世界的 `state`，页面据此重取 `/api/levels`（不能一发命令就去取，那时 `current` 还是旧值）。
