# 内核全景（表达器接入用）

> 写这份文档的原因：原型即将从「JS 复刻内核」改成「内核在后台真跑、界面只做表达」。
> 改造前必须先把内核**当成一个可被驱动的机器**理解清楚：它有哪些入口、时间怎么走、
> 世界变了怎么通知、订单怎么被执行、失败算什么。
> 本文只写**表达器必须知道的事**，不重复 UML（见 `UML/`）与设计规范（见 `docs/`、`demo/过程呈现_设计.md`）。

## 0 一句话

内核 = **确定性 tick 仿真**（逻辑时间）+ **命令日志**（可回放）+ **三个事件面**（世界信号 / 过程日志 / 表现帧）。
表达器只做三件事：**发命令、读状态、放帧**。任何"规则判断"都不该出现在表达器里。

## 1 运行形态（已实测）

```bat
dotnet run --project src/JarSystem.Web\JarSystem.Web.csproj -c Release
```

- 实际监听 **http://127.0.0.1:5289**（来自 `src/JarSystem.Web/Properties/launchSettings.json`；
  `Program.cs` 里那句 `UseUrls("http://127.0.0.1:3457")` 只在没有 launchSettings / 未设 `ASPNETCORE_URLS` 时生效）。
- `GET /api/state` → 完整世界状态（实测返回：`workshops[]`，每台含 `index/name/baseMarks/additionalMarks/ban/maxJars/maxLiquids/jars/liquids/canPourShapes/isMaster/isSlave`）。
- `WS /ws` → 双向：上行命令、下行消息（见 §3、§4）。
- `wwwroot/` → 已有一个最小页面（`index.html` + `css/` + `js/`，长任务详见其自身）。
- 串行闸门：`JarSystemService.Gate`（`SemaphoreSlim`）被 `/ws`、`/api/state`、定时器、自动检查**共用** ⇒ 外部看到的永远是"命令之间"的一致状态。
- 世界配置来自 `config/world.json`（启动即校验；`[world] loaded: …（工作台 4 个，生产者 4 个）`）。

## 2 时间：一条逻辑时间轴，五段流水线

`TickPipeline.AdvanceOneTick()` = `_clock.Advance()` → `WorldScheduler.RunTick(tick)`；
`TickPhase` 固定五段、次序不可换：

| 阶段 | 谁 | 做什么 |
|---|---|---|
| `Events` | `ProcessSystem.DrainEvents` | 执行上一 tick 攒下的世界事件（级联落点） |
| `Modifiers` | `ModifierStack.Expire` | 修饰器到期的清理 |
| `Processes` | `AdvanceActive` | 推进所有活动过程（每过程每 tick 至多一个单位） |
| `Production` | `ProductionService.TickStep` | 产线产出进**仓库** |
| `Flow` | `ProductionService.FlushFlow` | **只在调用边界**跑：仓库 → 主台（每 tick 3 罐 / 每液 2 份） |

- `JarSystem.Tick(count)`：循环 `AdvanceOneTick` 后执行一次 `RunCallBoundary()` ⇒ `Tick(4)` 与四次 `Tick(1)` 世界一致。
- **时间冻结**：`PauseTime()` 后 `Tick` 直接 `return 0` —— 不推进时钟、不跑任何阶段、**不写命令日志**（回放安全的前提）。
- "多久推进一次"是宿主的参数（`JarSystemService.TickIntervalMs`），**不进判定**。
- `WorldTime` 只是 `LogicalClock.Tick` 的只读投影（`ElapsedSince`、`FrozenAtTick`）。

## 3 命令面：21 条（`CommandDispatcher` 是唯一契约点）

```
getState createOrder createRandomOrder createWorkshop createRandomWorkshop updateWorkshopCapacity
setMaster setSlave executeOrder deleteOrder startOrder cancelProcess setTickInterval
checkFeasibility checkAllFeasibility manualTick reset updateProducerRate startTick stopTick setAutoCheck
```

与原型玩法直接相关的对应关系：

| 原型动作 | 命令 |
|---|---|
| 铺产线 / 调速率 | `updateProducerRate` |
| 换主台 / 换从台 | `setMaster` / `setSlave` |
| 推进一回合 | `manualTick`（一次 = 一 tick）；连续推进 = `startTick` / `stopTick` |
| 下单 | `createOrder`（含 `createRandomOrder`、模板单） |
| 看某单进度/可行性 | `checkFeasibility` / `checkAllFeasibility` |
| 执行某单 | `startOrder`（起过程）或 `executeOrder`（同步执行） |
| 取消进行中的过程 | `cancelProcess` |

## 4 下行消息：帧流（S1 已切换）

**S1 已完成**：Web 壳的 `PresentationObserver` 订阅核心的 `PresentationFeed`，
每帧转发一条 `frame` 消息，载荷就是帧的七个引用字段
（`seq` / `kind` / `op` / `subject` / `subjectId` / `tick` / `revision`）。
原 `ProcessObserver` 的 5 条 `process*` 消息已删除 ⇒ `PROTOCOL-OK (commands=21, messages=12)`。

理由：那 5 条是**宿主自己翻译的词汇表**（started/progressed/blocked/…），
而内核早有正式的帧流；宿主该做的是转发，不是再定义一遍。
帧只带引用，明细由客户端回查 `getState`（`processes` / `workshops` / `orders`）。
`kind` 的取值映射在 `PresentationObserver.KindName`，兜底分支**抛异常**（新增一类帧必须是一次有意识的改动）。

## 5 状态面：订单 / 过程 / 工作台

- 订单 `Order`：`Id`、类型（A/B）、需求列表（**空罐在前、满罐在后**）、状态、`FeasibilityResult`。
- 需求上限 **10**（`Config/Constants.MAX_ORDER_REQUIREMENTS`），构造期校验。
- 过程 `ProcessInstance`：`Id`、`Kind`（`order_execution` / `workshop_migration`）、`Subject`/`SubjectId`、
  `State`（Created/Ready/Running/Blocked/Succeeded/Failed/Aborted）、`AppliedSteps`、`DeclaredSteps`、
  `NextUnitTick`、`DeadlineTick`、`GraceTicks`。
- 工作台 `Workshop`：四个 public 端口（`PourIn` / `PourOut` / `ReshapeEmpty` / `ReshapeFull`，全返回
  `(bool Success, string? Reason)`）；`Jar` 的变更方法全 `internal` ⇒ **端口是唯一的门**
  （机器门：`test/JarSystem.Tests/WorkshopWritersTests.cs`，九条写入路径全部登记）。

## 6 可行性：进度条的唯一合法来源

`FeasibilityResultData`（`src/JarSystem.Core/Orders/Order.cs:128`，除 `timestamp` 外全部 `init`）：
`feasible` / `undetermined` / `blockage` / `reason` / `directCount` / `operationCount` / `timestamp`
+ 四个只读集合（求解路径等）。

读法（**这三条合起来才是契约**）：

| 字段组合 | 含义 | 表达器该显示 |
|---|---|---|
| `feasible=true` | 确定可行，且给了路径 | 进度**拉满**，可执行 |
| `feasible=false, undetermined=false` | **确实不可行** | 进度按 `directCount/需求数`，并显示 `blockage` |
| `feasible=false, undetermined=true` | 预算耗尽，**未判定** | 显示"⚠ 未判定"，**仍允许执行**（由贪心兜底） |

求解器三层（都实现 `ISolver`）：`StateSpaceSolver`（参照）、`PrecheckedStateSpaceSolver`（前置检查后委托）、
`MatchingSolver`（分配形）。B 类订单的"主台预处理 → 选择性转移 → 从台继续"由 `Orders/Feasibility/PartitionSearch` 负责。

## 7 执行与失败：谁动手、代价是什么

- `startOrder(index)` 起一个 `order_execution` 过程；过程按"一步一单位"推进（`ProcessInstance.NextUnitTick`）。
- 有求解器路径时走 `MasterPath` / `SlavePath`（逐条施加 `SolverStepDto`，由 `Executor/SolverStepApplier` 施加，
  施加前校验形状/液体/`IsMarked`）；没有路径时走 `MasterGreedy`（贪心一次跑完）。
- **B 类转移**：`OrderEvent.TransferredJarIds` 记录实际转移的罐子，供执行守卫与审计；
  终态回落不按输入账目筛选，而是排空从台当前全部剩余罐子与游离液体；
  成功/失败/结束时 `SlaveRollback` 把从台**当前剩余的全部**罐与游离液体回流主台，
  包括未交付工具罐和工具罐倒出的多余液体；容量或禁令溢出的直接丢弃。
- **失败要付代价**（`规则.txt:33-37`，设计定案）：主台上已发生的操作**不回滚** —— 改形保持新形状、
  成本液体不返还、已倒出的液体留在池子里；**只有跨台转移**回滚。表达器不得把它当 bug 修掉。
- 换台迁徙：`BeginSwitch → RunReshape → RunTransfer`，与订单**互斥**（互相拒绝）；无资源时直接改指针不起过程。

## 8 世界变了怎么知道（回答"检验为什么是时间驱动的"）

内核的时间驱动检查有三处，**表达器不该自己再写一个"执行完就检查"的同步循环**：

1. **`FeasibilityInvalidationReactor`**（`World/IWorldReactor`）：世界一变的信号进总线，反应器按
   **`WorldSignature` 内容指纹**判断待定订单的可行性缓存是否过期（不按修订号 —— 因为 `Tick` 每 tick 都写
   `WorldOps.Tick`，按修订号会每 tick 失效一次）。过期就**清空缓存**，下次查时自然重算。
2. **`AutoCheckBackgroundService`**：宿主定时（约 5 s）跑 `checkAllFeasibility`，但因为有指纹比较，无变化时不重算。
3. **tick 流水线**本身：产出/流入/过程推进都在 tick 内发生 ⇒ "资源变了"天然是 tick 事件。

⇒ 表达器的正确姿势：**推进 tick（或点执行）→ 内核发帧 → 界面按帧更新 → 需要进度时向内核要最新可行性**。
"执行完一单后重新监测"不是表达器的动作，是内核缓存的自然失效 + 下一次查询。

## 9 三个事件面（职责唯一，不得互换）

| 面 | 类型 | 面向 | 谁消费 |
|---|---|---|---|
| `WorldBus` / `WorldSignal` | 粗粒度广播（`WorldChanged`/`ProcessChanged`/`TimePaused`/`TimeResumed`，只带 tick+revision） | 世界内部（允许 `IWorldReactor` **改世界**） | 反应器 |
| `ProcessJournal` | append-only 审计（`seq` 单调、`StepIndex`/`Operation`、有界 4096、满则成批丢最旧一半、`FirstSeq == DroppedEntries+1`） | 审计与"某次执行做了哪些步" | 诊断 / `StepsFor` |
| `PresentationFeed` | 帧流（`seq/kind/op/subject/subjectId/tick/revision`，`Since(cursor)`） | 表现层投影（**只带引用、不带载荷**） | 宿主界面 |
| `CommandLog` | 世界级意图（可回放，`REPLAY-OK` 守它） | 回放与对拍 | 门禁 |

**新增第四个面之前必须先证明前三个表达不了**（`CONSTRAINTS.md` 的既定纪律）。

## 10 层序（机器检查，`test/JarSystem.Tests/ArchitectureTests.cs`）

```
L0 Config   L1 Domain   L2 Abstractions   L3 Presentation   L4 Rules   L5 Production
L6 Solver   L7 Commands L8 Orders         L9 Process        L10 Services
L11 Sessions L12 Executor L13 World       L14 Bootstrap
```

规则一句：**一个层只许引用排位比自己低的层**。表达器属于宿主（`src/JarSystem.Web`），不在核心层序内。

## 11 表达器改造的五步（与用户裁决对齐）

| 步 | 内容 | 判据 |
|---|---|---|
| **S1** ✅ | Web 壳的推送从 `ProcessObserver`（5 条消息）切到 `PresentationFeed`（一条 `frame`） | 门禁全绿 + `PROTOCOL-OK (commands=21, messages=12)` + `REPLAY-OK` 字节不变 |
| **S2** ✅ | 新的只读页 `wwwroot/world.html` + `js/world.js`：连 `/ws` 显示帧时间线、`getState` 世界、以及 `GET /api/invariants` 的不变量面板（页面不推导，只显示内核给的答案） | 打开 `/world.html` 能看到帧在动、不变量显示「世界自洽」 |
| **S3** | 用内核命令打通**第一关**（选台 / 铺产线 / 推进 tick / 下单 / 起单 / 看过程）；页面里不再有 JS 规则 | 第一关通关，过程与内核 `StepIndex` 一致 |
| **S4** | 订单进度条 = `directCount / 需求数`（`feasible` 时拉满），`blockage` 作说明 | 第二关 #2 显示进度；拉满时可一键执行 |
| **S5** | B 类转移（第二关）—— 内核本来就会算（取证：朱雀池 `feasible=True`，路径 `RESHAPE→POUR_IN`） | 那条路径在过程里逐帧出现 |

**玩法的三条语义（用户裁决，不要改）**：
① 进度条每单独立；② **完整可执行 = 进度拉满**；③ 一回合**连续执行**所有"当前完整可执行"的单，
每执行完一单后**由内核的时间驱动机制**重新监测（不是表达器自己循环）。
