# World v2 阶段二：主从工作台岗位与替换过程

## 本阶段目标

在阶段一的逻辑时间与资源区之上，建立当前世界唯一的一套主/从工作台岗位，并让岗位替换由逻辑时间推进。

本阶段不引入多套主从组合，不实现订单求解器、订单 CD 或完整订单调度器。

## 概念与状态归属

| 概念 | 拥有的状态 | 不负责 |
|---|---|---|
| `Workshop` | 单台工作台的能力、罐子、游离液体、容量与资源操作 | 决定自己属于主岗位还是从岗位 |
| `WorkshopCapability` | 基础标记、附加标记、禁令等不可变能力参数 | 持有资源 |
| `WorkshopRoster` | 工作台集合、当前 Master、当前 Slave | 复制工作台资源或执行加工 |
| `WorkshopReplacementProcess` | 替换目标、替换角色、阶段、阶段已消耗逻辑时间、成功/失败 | 拥有工作台资源库存 |
| `WorkshopSwitchEvent` | 主台迁徙的快照、重组规则、资源转移规则和回滚 | 订单状态与 CD |
| `IOrderInterruptionPort` | 对订单系统提出中断请求的边界契约 | 定义订单内部状态机 |

## 岗位规则

1. 一个 `WorkshopRoster` 只代表一套主从组合。
2. Master 与 Slave 必须是不同的工作台对象。
3. 岗位只能指向已登记在该 Roster 中的工作台。
4. 备用工作台是既不等于 Master 也不等于 Slave 的登记工作台。
5. Slave 替换目标必须为空；主台替换目标沿用旧迁徙规则，不额外要求为空。
6. 替换完成前岗位指向不改变；替换失败或取消时保持原岗位指向。
7. 工作台对象本身不因岗位替换而复制或重建。

## 主台替换

主台替换复用旧系统 `WorkshopSwitchEvent` 的两阶段规则：

1. `RunReshape`：依据新旧主台禁令是否相同，运行 Case 1 / Case 2。
2. `RunTransfer`：按新主台价值策略转移剩余罐子与液体，容量不足或禁令不允许的资源按旧规则丢弃。
3. 两阶段都成功后，`WorkshopRoster.Master` 才指向新主台。

每个阶段消耗 `phaseDurationMilli` 逻辑时间。这个时长是新世界显式配置，不把旧 ProcessSystem 的整数 tick 直接解释为逻辑时间。

迁徙取消或失败时，`WorkshopSwitchEvent.Rollback` 恢复迁徙开始时两台的快照。注意：快照在订单中断接口成功之后才建立，因此不会把已结算的订单临时资源“复活”。

## 从台替换

从台替换不搬运主台资源，也不套用主台 Case 1 / Case 2：

1. 目标必须是备用工作台且为空。
2. 请求经过订单中断边界。
3. 等待一个配置的逻辑时间阶段。
4. 完成时将 Slave 岗位指向目标工作台。

旧从台在订单中断结算后应为空，并成为备用工作台。

## 订单中断边界

`IOrderInterruptionPort.InterruptForWorkshopReplacement()` 是后续订单阶段需要实现的适配接口。

其成功契约是：活动订单已经停止、该订单已进入自己的 CD、从台临时资源已经按照订单规则结算。没有活动订单时应成功返回且不产生副作用。

本阶段没有伪造订单 CD，也没有把旧 `OrderEvent.Fail()` 当成 CD。旧订单终态失败语义与新世界可再次求解的 CD 语义不同，必须在订单阶段实现真实适配器。

## 世界时间接入

`ResourceWorldRuntime` 可选持有 `WorkshopRoster`。通过 `BeginReplacement` 启动替换，通过 `AdvanceWorldTime(delta)` 推进：

- 时钟先把世界时间换算成逻辑时间。
- 替换过程消费同一份逻辑时间。
- 替换过程活动期间，生产继续进入中央仓库。
- 替换过程活动期间，仓库到主台的流入关闭。
- 与替换过程重叠的整个 runtime 推进片段都不流入；即使过程在片段中途完成，也从下一次推进开始恢复流入。这样不伪造片段内的精确子步边界。

旧的 `AdvanceWorldTime(delta, master)` 重载仍保留，以兼容阶段一调用方式。

## 明确不在本阶段实现

- 订单自身的 CD 计时与 ReadyForSolve / HasSolution。
- 真实订单执行中断、从台清算和订单 CD 状态转换的适配器。
- 主动/被动需求区、求解与调度。
- 多套主从组合。
- 工作台能力参数在线编辑流程。

## 测试覆盖目标

- Roster 拒绝同一工作台同时占据主从岗位。
- 从台替换只在逻辑时间达到阈值后提交。
- 非空备用工作台不能成为从台。
- 主台替换分两阶段执行，并移动原 Jar 对象。
- 主台迁徙取消会恢复已重组资源。
- 替换期间继续生产，但暂停资源流入。
