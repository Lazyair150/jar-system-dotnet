# 4.10b-9d：B 类订单资源边界与替代资源组

> 状态：领域数据契约与不变量已建立；从台规则分解器、边界提取算法和运行时监听器尚未实现。

## 求解方向

B 类订单不再先猜测主台交接液体数量。正确方向是：

1. 将订单最终需求交给从台规则环境，从从台视角分解目标。
2. 从台规则分解遇到必须由主台提供的资源时，输出边界条件。
3. 边界条件形成一个资源组；组内条件是 AND。
4. 从台存在多条可行规则路径时，形成多个替代资源组；组与组之间是 OR。
5. 停止该分支在当前从台环境下的递归展开，不把从台分支继续送回主台规则分解器。
6. 运行时监听资源组条件；任意一组当前全部达成，才进入交接资格检查。
7. B 类订单仍只执行一次主台到从台的原子批量交接。监听器不创建补给事件，也不触发第二次迁徙。

## 契约

新增 `WorldOrderBoundaryRequirement`：

- `FreeLiquid`：主台必须在交接边界提供指定种类和数量的游离液体。
- `JarState`：主台必须提供指定形状和内部液体状态的 Jar。
- 每个条件记录提供岗位、使用岗位、来源操作和来源需求索引。
- 该对象是规则推导出的条件，不是库存余额、预留、物理 Jar ID 或交接命令。

新增 `WorldOrderResourceRequirementGroup`：

- 一个组表示一条从台规则路径所需的完整边界资源组合。
- 组内所有条件必须同时满足。
- 不允许同一组混入不同的提供/使用岗位方向。

新增 `WorldOrderResourceRequirementAlternativeSet`：

- `Complete` 表示这一层规则分解已穷尽并得到完整替代集合，不代表资源当前可用。
- `Infeasible` 表示完整分解后没有可行资源组。
- `Undetermined` 表示预算或规则不透明等原因导致分解未完成；可以保留已发现的部分资源组，但不能宣告无解。
- 规则版本、工作台属性版本和订单规格版本必须随集合保存，避免跨规则/工作台配置复用旧条件。

## 关键不变量

### 替代关系不能被求和

例如：

- 组 A：X 液体 3 单位 AND Y 液体 2 单位
- 组 B：Z 液体 5 单位

这代表 `(X >= 3 AND Y >= 2) OR (Z >= 5)`，绝不能压成一个包含 X、Y、Z 的总需求。同一组内若多个步骤都需要 X，必须先将数量相加（例如 X 3 + X 2 = X 5），再与交接时主台的同一份 X 余额比较；不能对同一余额分别做局部检查。原始条件仍保留来源操作，供追踪和诊断。

### Jar 与游离液体不能混为一谈

Jar 状态条件表示需要交接一个符合指定状态的 Jar；游离液体条件表示需要交接工作台 staging 中的独立液体。Jar 内液体不是游离液体余额，也不能拿来满足游离液体条件。

### 边界方向固定

本阶段的边界是 Master 提供、Slave 使用。主从账户独立；从台自身在交接后通过规则操作产生的液体，只能供从台后续操作使用，不应被反向计入主台交接需求。

### 一次性交接

资源组满足仅表示有一条规则路径具备边界条件。真正交接前仍需验证：
- 主台在交接时刻实际拥有所需游离液体；
- 从台接收容量和拒收规则允许整个批次；
- 需要的 Jar 身份与状态确实可交接；
- 所有 Jar 和游离液体在同一个唯一 handoff 节点中原子迁移。

若检查失败，不能通过重复 handoff 或追加补给来修补同一 B 类订单。

## 与现有阶段的关系

- 9b：提供有序符号操作程序基础。
- 9c：模拟岗位本地 staging、产液/消耗和唯一交接的原子资源变化。
- 9c2：将显式准备操作加入有序程序。
- 9d 本切片：只定义从台规则分解结果的边界条件和 OR/AND 资源组模型。
- 后续切片：实现从台规则反向分解、边界截断、资源组提取；再实现运行时监听与交接资格检查。

## 明确不宣称

当前契约不自动推导资源组，不绑定物理 Jar，不检查当前余额，不做运行时监听，不预留资源，也不宣称订单已可执行。不得将 `Complete` 解释为资源可用或订单完成。
