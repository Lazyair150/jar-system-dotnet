# 4.10b-9c：按操作顺序模拟岗位资源账户

> 状态：9c 的固定程序/固定交接输入顺序重放内核已实现；9l 已将其集成到 A/B 分支枚举、操作顺序搜索、一次性交接向量推导和具体计划/Manifest 验证中。

## 本切片的输入边界

`WorldOrderSymbolicResourceSimulator` 接收：

- 已排序的 `WorldOrderSymbolicOperationProgram`；
- 主台订单作用域的初始游离液体余额及其聚合 staging 容量；
- 从台 staging 容量；
- 唯一 handoff 节点要转移的固定液体数量向量。

从台初始游离液体余额固定为零。A 类没有从台资源账户，也不得传入交接液体向量。主台初始余额在本模拟中代表已经完成订单资金准备后的主台订单作用域余额；本模拟不替代 Prefill / ShipInventory 的来源核算或 Admission 资金预留。

## 顺序语义

每个规则操作按程序节点顺序执行：

1. 先检查并消耗该操作需要的游离液体；不足时，该候选程序立即失败。
2. 再处理 Jar 内液体自耗。它单独记账，不读取或减少游离液体 staging。
3. 操作产生的游离液体进入当前岗位的 staging。若该岗位拒收该液种，则整份产液被拒收并丢弃；否则容量按所有液种共享，有空位则接收，超出的部分记录为 overflow discard，不会凭空留在账户中。
4. 后续步骤只能使用实际留在该岗位账户中的余额。

因此，前置 PourOut 产生的液体只有在当时被 staging 接收后，才可能供后续操作使用。不能用全局毛产出抵扣毛消耗，也不能把主台余额与从台余额合并。

## 唯一一次主从交接

B 类程序只在唯一 `MasterToSlaveHandoff` 节点处理交接：

- 先一次性检查交接总量是否能放入从台 staging；
- 再检查主台对每一种液体是否都有足够余额；
- 所有检查通过后才同时扣减主台、增加从台，保证这笔交接对两个账户是原子的；
- 任一液种不足或从台容量不足时，不发生部分转移，失败结果保留交接前的两边余额；
- handoff 节点执行后不再存在第二次补给机会。

本切片模拟的是调用方提供的固定交接向量，不负责推导“最小且足够”的数量。它也不允许从台初始库存补差。

## 结果记录

每个岗位分别返回：

- 最终游离液体余额；
- staging 聚合容量与过程峰值；
- 游离液体生产的 accepted / rejected / overflow-discarded / total-discarded；
- 游离液体消耗；
- Jar 内液体自耗。

结果同时记录 handoff 是否实际发生、实际交接向量和失败节点。失败只说明**这一个固定程序、初始余额、容量和交接向量组合**不可行；不能直接据此宣告整个订单无解，求解器仍须尝试其他候选程序或操作顺序。

## 回归覆盖

`WorldOrderSymbolicResourceSimulatorTests` 覆盖：

- 主台产生的游离液体经过唯一 handoff 后由从台消费；
- 多液种共享 staging 容量与溢出丢弃；
- 工作台拒收的产液被丢弃，不能作为后续 handoff 资源；
- 从台拒收交接液种时，整个一次性交接原子失败；
- 已被丢弃的产液不能在后续 handoff 中再次使用；
- handoff 容量不足和主台余额不足时，两个账户均不发生部分转移；
- Jar 内液体自耗不影响游离液体账户；
- A 类拒绝交接向量；
- 主台初始订单余额不能超过其 staging 容量。
