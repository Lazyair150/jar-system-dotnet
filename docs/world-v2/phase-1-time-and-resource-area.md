# World v2 — 阶段一：时间与资源生产区

本阶段建立一个**不依赖订单系统**的持续运行世界切片。它只包含：

- 世界时间与逻辑时间换算；
- 按形状生产罐子；
- 按品种生产游离液体；
- 资源区库存（复用现有中央仓库）；
- 按逻辑时间吞吐速率向当前主工作台流入资源。

本阶段不接入订单、求解、CD、工作台替换、从工作台或多工作台组合。

## 2. 时间单位

所有时间与速率都以千分之一为内部单位：

- `1000` 世界时间单位 = 1 个世界时间单位；
- `1000` 逻辑时间单位 = 1 个逻辑时间单位；
- `1000` 流速倍率 = 1 倍。

换算关系：

```text
logicalDelta = worldDelta × speedRatio
```

`WorldClock` 使用整数和除法余数保存换算状态。相同的世界时间总量，即使拆成多次 Advance，也会得到相同的逻辑时间总量。

暂停时世界时间和逻辑时间都不推进。流速为 0 时，世界时间继续记录，逻辑时间不推进。

## 3. 生产速率

罐子生产器速率单位为：

```text
罐子个数 / 逻辑时间
```

液体生产速率单位为：

```text
液体份数 / 逻辑时间
```

两种生产仍由不同概念负责：

- `ShapeProductionLine` 按形状汇总多个生产者；
- `LiquidProduction` 按液体种类维护世界液体产能。

两者都将速率在注册/设置边界转换成千分之一定点数，并使用百万分之一资源单位累计速率与时间的乘积。旧的 `Tick()` 入口仍保留，一个旧 tick 等价于 1 个逻辑时间单位。

## 4. 资源区与流入

`ResourceArea` 不复制库存。真实库存仍由现有 `ProducerModule.Warehouse` 持有：

- 罐子是独立 `Jar` 个体；
- 游离液体按品种计数；
- 生产先进入资源区库存；
- 有主台时，再按本时间片流入额度调用现有 `Warehouse.FlowToMaster`；
- 没有主台时，资源留在资源区，不会丢失。

罐子流入继续复用旧仓库规则：优先选择主台基础标记对应形状，否则按仓库现有顺序取用。液体继续按词表顺序流入，禁令不阻止存储，只限制取用。

### 流入速率必须显式配置

旧世界的 `FlowSettings` 是“每次宿主调用流入多少”，不是“每逻辑时间流入多少”。二者不能直接视为同一个单位。

因此新 `ResourceArea` 要求装配时显式传入：

- `jarFlowRate`：每逻辑时间最多流入多少只罐子；
- `liquidFlowRate`：每逻辑时间、每种液体最多流入多少份。

本阶段没有擅自把旧版每次调用的 3 罐 / 2 液体改写成每逻辑时间速率。后续接入世界配置时，应由世界配置明确给出新单位下的数值。

流入额度是吞吐上限，不是欠条：本时间片没有库存或主台没有容量时，未使用的整数额度不会累积到下一时间片；不足一份的定点余数会保留。

## 5. 运行顺序

`ResourceWorldRuntime.AdvanceWorldTime` 的顺序固定为：

1. `WorldClock.Advance`：世界时间换算成逻辑时间；
2. `ProducerModule.AdvanceLogicalTime`：生产罐子并放入仓库；
3. `LiquidProduction.AdvanceLogicalTime`：生产游离液体并放入仓库；
4. 若存在主台，`Warehouse.FlowToMaster`：罐子先流入，液体随后流入。

这个顺序确保同一时间片新生产的资源可以进入主台。

## 6. 与旧世界的兼容边界

- 旧 `JarSystem`、`ProcessSystem`、整数 tick、回放和 Web API 没有改接新运行时；
- 旧 `ProducerModule.Tick(count)` 和 `LiquidProduction.Tick()` 保留；
- 新世界通过 `ResourceWorldRuntime` 使用连续时间；
- 旧中央仓库、罐子实体、液体库存和工作台接收规则继续复用。

这是一条独立的新世界运行路径，而不是偷偷改变旧世界 tick 的含义。

## 7. 验证

本阶段新增测试覆盖：

- 世界时间与流速倍率换算；
- 分段推进与一次性推进结果一致；
- 暂停；
- 零流速；
- 罐子和液体按逻辑时间生产；
- 资源区向主台流入；
- 没有主台时资源留在资源区；
- 世界运行时把倍率后的逻辑时间传递给资源区。

当前通过 GitHub 连接器提交了测试源文件，但尚未在本地 .NET SDK 环境执行测试。因此不能把新增测试标记为已通过。合并前需要在项目环境执行：

```powershell
dotnet test test/JarSystem.Tests/JarSystem.Tests.csproj
```

## 8. 下一阶段前的明确边界

本阶段完成后，世界能够在没有订单的情况下持续生产资源，并根据显式配置的逻辑时间流入速率向一个主工作台输送资源。
