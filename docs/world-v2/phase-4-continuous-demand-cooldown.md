# World v2 — 4.6：持续订单 CD 生命周期闭环

## 目标

让持续订单成功后的下一轮执行完全由订单自身 CD 控制。此阶段修复既有生命周期，不引入新的 rearm manager、资源变化唤醒策略、后台计时器或新的调度优先级。

## 唯一生命周期规则

| 事件 | 区域归属 | CD | 求解簿状态 |
|---|---|---|---|
| 新订单加入 | 保留 | 不启动 | Dirty |
| 持续订单成功，CD > 0 | 保留 | 启动该订单自己的完整 CD | NotReady |
| 持续订单成功，CD = 0 | 保留 | 无等待 | Dirty |
| CD 推进但未结束 | 保留 | 递减 | NotReady |
| CD 到期 | 保留 | 归零 | Dirty |
| 一次性订单成功 | 卸载 | 不启动 | Detached |
| 普通执行失败 | 保留 | 不启动 | Dirty，按当前世界重新求解 |
| 工作台替换中断 | 保留 | 启动该订单自己的 CD | NotReady；CD 为 0 时立即 Dirty |
| 订单在区域间移动 | 移动 | 保留原 CD 剩余值 | CD 中则 NotReady，否则 Dirty |

## 职责归属

- `OrderDemand`：持有 CD 时长、剩余时间和是否具备求解资格。
- `OrderDemandBoard`：持续订单成功时按区域策略保留订单并启动其 CD；一次性成功时卸载订单；按逻辑时间推进 CD 并发布到期事件。
- `WorldOrderSolveBook`：把 CD 作为求解硬门槛。CD 中始终为 NotReady；CD 到期自动 Dirty。单项或全局失效不得绕过 CD。
- `WorldOrderScheduler`：不管理 CD。它只按现有规则处理 Dirty/Current/NotReady；被动自动启动，主动只响应显式启动请求。
- `ResourceWorldRuntime`：仍是唯一逻辑时间推进者，订单 CD 与生产、执行使用同一逻辑时间增量。

## 时间顺序

一次 Runtime 世界推进的顺序保持不变：

1. 推进世界时钟并得到逻辑时间增量。
2. 推进当前已装载订单的 CD；刚到期的订单发布 `CooldownElapsed`，求解簿转为 Dirty。
3. 推进生产与资源流入。
4. 推进本片段开始前已登记的执行会话。

如果某张持续订单在第 4 步成功，它在结算时启动完整 CD。该 CD 不会被同一个时间片提前扣减，从下一个 Runtime 世界推进片段开始倒计时。

## 关键不变量

1. CD 是订单自身的资格门槛，不是求解缓存状态。
2. `MarkDirty`、`MarkAllDirty`、世界快照版本变化、区域移动都不能让 CD 中订单变成可求解状态。
3. CD 到期由需求板事件自动触发 Dirty，不需要上层显式调用 rearm。
4. 被动持续订单 CD 到期后按被动列表顺序自动竞争。
5. 主动持续订单 CD 到期后只重新求解，仍需用户显式启动。
6. CD 为 0 时持续订单成功后立即 Dirty；同一调度轮次不会再次遍历同一订单。
7. 一次性成功不进入 CD；普通执行失败不进入 CD；工作台替换中断继续进入 CD。
8. CD 不重置世界资源、不回滚已消耗资源、不改变资源预留与执行结算语义。

## 回归测试范围

- 主动与被动持续订单成功后都启动各自 CD。
- 不同订单 CD 时长独立。
- CD 中的单项 Dirty 与全局 Dirty 均保持 NotReady。
- CD 到期自动 Dirty 并重新求解。
- 被动持续订单到期后自动再次启动。
- 主动持续订单到期后重新求解但不自动启动。
- CD 为 0 时立即 Dirty。
- 一次性成功不启动 CD。
- 普通执行失败不启动 CD。
- 工作台替换中断仍启动 CD。
- CD 与世界时间共用 Runtime 逻辑时间。

## 非目标

- 不创建 `RearmManager`。
- 不根据任意资源变化自动唤醒持续订单。
- 不增加后台 timer、线程或帧循环。
- 不改变主动/被动之间的全局优先级。
- 不改变求解器、资源清单、准入、预留、执行步骤、结算和世界故障边界。
