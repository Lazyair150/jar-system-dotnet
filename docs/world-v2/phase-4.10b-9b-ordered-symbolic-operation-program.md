# 4.10b-9b：有序符号操作程序与单次交接边界

> 状态：符号程序结构已建立；尚未把现有候选解集自动编译为完整程序，也未完成资源数量/容量证明。

## 本切片解决的问题

4.10b-9a 将 Master / Slave 的资源效果分账，但每条需求仍只选择一个单步候选。它不能表达：

- 同一个抽象 Jar 在多个步骤中的状态演进；
- 前置 PourOut 如何为后续操作产生游离液体；
- 依赖边如何保证 Jar 状态和液体供给先于消费者；
- B 类订单的资源交接必须是一个唯一事件，而不是按步骤重复调用。

本切片新增 `WorldOrderSymbolicOperationProgram` 及节点、Jar 状态版本和依赖边模型，并增加 `BuildDirectCandidateProjection`，将现有每需求单步候选解投影为有序节点图，为这些约束提供不可变的结构承载。

## 核心领域不变量

### 1. 一个 Jar 身份，多个连续状态版本

- `JarKey` 是抽象物理 Jar 身份，不是运行时 Jar ID。
- 每次规则操作消耗一个状态版本并产生同一身份的下一版本。
- 同一个 `(JarKey, Revision)` 不能被两个操作重复消费，也不能由两个操作重复产生。
- 如果某个输入版本由程序中的前置操作产生，必须有显式 JarState 依赖边。
- Jar 依赖边连接的是完整一致的状态事实（身份、版本、岗位、形状、液体），不能只靠相同编号拼接。

### 2. B 类主从资源迁徙是唯一一次交接

B 类程序必须且只能包含一个 `MasterToSlaveHandoff` 节点：

- 所有 Master 规则操作位于该节点之前。
- 所有 Slave 规则操作位于该节点之后。
- 交接节点作为一个批次边界，可承载零个或多个抽象 Jar 的岗位归属变化。
- 每个被交接的 Jar 保留同一 `JarKey`，但进入 Slave 后使用新的状态版本。
- B 类从台规则操作的 Jar 输入必须由唯一 handoff 或更早的从台操作产生；不允许从台自有初始 Jar 库存。
- 从台的游离液体消耗必须显式依赖 handoff 的该液种输入，或更早的从台产液操作；不能凭空从从台初始游离液体余额取用。
- 游离液体的岗位依赖必须经过这个唯一交接节点；禁止 Master 直接连到 Slave 的游离液体依赖边。
- 不允许把一次交接拆成多个节点，也不允许通过第二次交接补充资源。

这不是“每步泵一次”，也不是资源不足时可重试的补给循环。程序结构只有一个主从迁徙位置。

A 类程序则完全不允许出现该节点，也不允许使用 Slave 岗位。

### 3. 依赖边与操作顺序

- `JarState` 边指明某个精确 Jar 状态版本从哪个节点产出、由哪个节点消费。
- `FreeLiquid` 边指明某种游离液体的供给依赖；精确数量可以在后续资源模拟阶段绑定。
- 依赖必须从较早序号指向较晚序号。
- 同一液体的 Master / Slave 账户不会因边关系而合并；跨岗位只能通过唯一 handoff 节点。
- 从台的每个游离液体消耗节点必须存在来自 handoff 或更早从台产液节点的同液种依赖边。
- 前置 PourOut 可以由节点模型以普通规则节点表达，`RequirementIndex = null` 对应候选目录中的 `RequirementIndex = -1`，不伪装成满足一条订单需求。当前直接候选投影器会拒绝把准备候选塞进需求解集，不会擅自挑选准备操作。

直接候选投影器为 Master 需求节点、唯一 handoff、Slave 需求节点分配确定性序号，并为 Slave 候选创建“Master 初始 Jar → handoff → Slave 操作”的抽象状态链。若 Master 单步候选产出的游离液体与 Slave 单步候选消耗的液体相同，会显式建立 Master → handoff → Slave 依赖边。该序号只用于表达当前直接候选投影的阶段顺序，不是完整操作调度结论。

## 当前边界

本切片建立的是**直接候选投影 + 结构模型 + 结构校验器**，并不声称已经完成：

- 从 `WorldOrderSymbolicSolutionSet` 枚举完整、多步、包含准备操作的全部候选程序；
- 选择真实或抽象 Jar 的完整分配路径；
- 枚举准备操作并解决其与需求操作的组合；
- 每一步的液体数量、初始账户余额、staging 峰值和拒收/丢弃模拟；
- 主台最终可交接的精确液体数量；
- Slave 只能使用一次交接获得的液体的完整资源证明；
- 真实 Jar ID、Manifest、Admission、Lease 或 Session 绑定。

尤其是 `FreeLiquid` 依赖边目前只表达先后和液种，不代表已经验证该岗位有足够余额。不得将结构合法误读为资源可行。

## 回归覆盖

`WorldOrderSymbolicOperationProgramTests` 覆盖：

- B 类程序恰好一个交接节点，且 Master → handoff → Slave 顺序成立；
- 前置 PourOut 可作为无需求索引的准备操作节点；
- A 类禁止交接；
- B 类缺失或重复交接被拒绝；
- Slave 操作不能提前到交接之前；
- 游离液体不能绕过交接节点直接跨岗位流动；
- 同一 Jar 状态版本不能被两个操作重复消费；
- 从台不能从自己的初始 Jar / 游离液体库存启动订单操作；
- 候选规则与输入/输出 Jar 事实必须一致；
- 直接候选投影生成唯一 handoff，并让 Slave 的游离液体依赖经过 handoff；
- A 类投影不生成 handoff；
- 准备操作和重复需求不能伪装成直接需求解。
