# 信任边界与代码安全架构

> 这份文档不是安全宣言，而是**证据索引**：每条断言都指到仓库里的一个文件与一处行为，
> 并且大部分都能用 `重构报告\security-gate.ps1` 或 `重构报告\verify.bat` 复跑出来。
> 凡是"这里其实没做"的地方，写在 §11「已知缺口」里，不藏在正文的乐观语气里。

## 1. 系统是什么（决定了威胁模型长什么样）

`JarSystem` 是一个**本地单机**的世界模拟内核 + 一层回环 Web 壳：

| 部分 | 形态 | 谁会用它 |
|---|---|---|
| `src/JarSystem.Core` | 纯 .NET 类库，**零第三方依赖** | 宿主（Web / Godot / 测试） |
| `src/JarSystem.Web` | ASP.NET Core 最小宿主，绑 `127.0.0.1`，6 个 HTTP 端点 + 1 个 WebSocket | 同一台机器上的浏览器页面 |
| `test/*` | xUnit v3 + FsCheck | 开发者在本地跑 |

由此推出三条前提，后面所有取舍都从这里来：

1. **没有远程用户，也没有多租户**：进程与浏览器同属一个 OS 用户，真正的身份边界是**操作系统账号**，
   不是应用层的登录态。所以本项目**没有**认证/会话/口令体系（§11 记为缺口，而不是假装有）。
2. **唯一的外部输入是"本机浏览器"与"作者手写的世界/关卡 JSON 文件"**，两者都按不可信处理（见 §4）。
3. **产物不发布到任何仓库/商店**，因此 SLSA 的签名链在本仓库只做到"可复现构建 + SBOM 归档"，
   签名与发布网关标为缺口（§9、§11），不用一句"内部项目所以不需要"糊过去。

## 2. 资产清单（什么被保护）

| 资产 | 损坏后果 | 存放 |
|---|---|---|
| 世界状态（工作台/罐/液体/订单/过程） | 玩法自相矛盾、存档不可回放 | 进程内存 `JarSystem` |
| 命令日志与过程日志（`CommandLog` / `ProcessJournal`） | 回放不再复现，历史被伪造 | 内存，`REPLAY-OK` 逐字节校验 |
| 作者数据 `config/world.json`、`config/levels/*.json`、`config/scenario.json` | 关卡/场景被悄悄改写 | 仓库文件 |
| 契约产物（`state_keys.txt`、`state.schema.json`、`contract.d.ts`） | 前后端协议漂移 | `重构报告/_contract` |
| 本机回环端口 3457/5289 | 本机其它进程读到世界状态、或驱动世界 | 仅 loopback |

"世界状态"不是资金，但它等价于**唯一真相**：一旦它可以被页面单方面改写，`REPLAY-OK` 这条证据就失效，
所以本项目的安全设计反复落在同一句话上 —— **服务端是唯一仲裁者，页面只是表达器**。

## 4. 每条边界上到底做了什么

| 边界 | 输入 | 校验 | 失败行为 | 证据 |
|---|---|---|---|---|
| **B1** 页面 → 宿主 | WebSocket 命令 JSON、HTTP 请求体 | ① Origin 校验（`/ws` 与 6 个端点同一判据）② Host 白名单（防 DNS rebinding）③ 命令名白名单 + 载荷键提取 ④ 每一类载荷有专门读取器（类型不符取默认值，不抛栈） | 403 / 400 / `{type:"error"}` | `WebSocketHub.cs:160` `IsAllowedOrigin`；`Program.cs` 六处 `if (!WebSocketHub.IsAllowedOrigin(...))`（98/117/146/179/192/205）；`CommandDispatcher.cs:356-359` |
| **B1'** 页面 → 宿主（资源边界） | 场景 JSON（POST `/api/scenario`） | 先过 `ScenarioJson.FromJson` + `Validate()`，**校验不过不落盘**；正文 ≤ 1 MiB（读取时累计字节，不信任 `Content-Length`）；保存路径固定 `config/scenario.json`（不接受任意路径）；同目录临时文件 + 原子替换 | 413 / `{saved:false, errors}` | `Program.cs` 的 `/api/scenario`、`ReadBodyWithinLimitAsync`、`ValidateScenarioText` |
| **B2** 宿主内部 | 命令参数 | 所有玩法规则住在 Core：`WorkshopRulebook.IsAllowed`（这一刻哪些操作合法）、`Workshop.TryReshape`（改形唯一入口）、`OrderService` + 求解器（可行性）、`Production`（产量与流入） | 抛 `DomainValidationException` / 返回 `(false, Reason)`，命令日志**不记录**被拒命令 | `Domain/WorkshopRulebook.cs`、`Domain/Workshop.cs`、`Services/*.cs` |
| **B3** 构建门禁 | 源码 | `verify.bat` 九步 + 质量底线 + 依赖漏洞/秘密扫描；门禁脚本本身必须纯 ASCII | `VERDICT=FAIL` 并非零退出 | `重构报告/verify.bat`、`quality-gate.ps1`、`security-gate.ps1` |
| **B4** 作者数据 → 内核 | `config/*.json` | 三处都 `UnmappedMemberHandling = Disallow`（未知键直接抛）+ `Validate()` 语义校验；关卡文件另有 `turns>0`、订单模板必须已定义等硬规则；**校验失败 = 拒绝启动**，不是先跑起来再警告 | 启动抛 `InvalidOperationException`，宿主退出 | `Config/WorldOptionsJson.cs:19-31`、`Rules/ScenarioJson.cs:13-18`、`Process/Journal/JournalCodec.cs:25-30`、`Sessions/SessionReplay.cs:120-128`、`Web/LevelCatalog.cs` |

## 5. 纵深防御（关键资产至少两条独立防线）

| 资产 | 第一层 | 第二层（机制不同） | 第三层（可验证） |
|---|---|---|---|
| 世界状态唯一真相 | 页面只发命令，状态只在服务端生成 | 命令走单一 `CommandDispatcher` 白名单，未知命令显式拒绝 | 命令日志 + 帧流 seq/revision，可回放比对 |
| 回放一致性 | 命令日志记录（含被拒命令不记录的口径） | 过程日志 10 键 JSON 定序 | `REPLAY-OK` 逐字节 + `state_keys.txt` 快照基线（漂移即 FAIL） |
| 作者数据的完整性 | 启动期强校验（Disallow 未知键 + Validate） | 保存前必须校验通过 + 原子替换（不会留半份文件） | 契约快照 `CONFIG-WORLD-MATCH`：配置世界 == 内置世界逐字节 |
| 本机端口 | 只绑 loopback | Origin + Host 双校验（浏览器跨源与 DNS rebinding 各自一条） | `/ws` 连接数上限 8 + 429；拒绝时打印来源到 stderr |
| 供应链 | 依赖锁定到具体版本，产品代码零第三方依赖 | 高危漏洞阻断 + 秘密扫描 | `SEC-OK` / `SEC-SECRETS-OK` 写进 `verify.bat` 的 VERDICT |

## 6. Saltzer & Schroeder 八原则对照

| 原则 | 本仓库怎么落地 | 证据 |
|---|---|---|
| 最小权限 | 页面没有"写世界"的权限，只有被枚举的 27 条命令；`/api/scenario` 只能写一个固定路径；Web 壳只绑 loopback | `CommandDispatcher` 的 27 个 `case`；`Program.cs` 的 `savePath` 固定构造 |
| 失败安全默认 | 未知命令 → `error` 帧（此前是静默丢弃，已修）；未知 JSON 键 → 抛；配置校验失败 → 拒绝启动；离线拿不到漏洞数据源 → 打印 `SEC-SCAN-SKIPPED` 而不是假装 OK | `CommandDispatcher.cs:356`；`WorldOptionsJson.cs:31`；`security-gate.ps1` |
| 完全仲裁 | 每个受保护动作都过一次检查：命令名、载荷形状、玩法规则（规则表）、可行性（求解器） | `Domain/WorkshopRulebook.cs`、`Orders/Feasibility/*` |
| 开放设计 | 安全不依赖"源码保密"：本文档、契约快照、门禁脚本全在仓库里；`REPLAY-OK` 是公开可复跑的判据 | 本文件 + `重构报告/` |
| 权限分离 | 高风险动作需两个独立条件：起单 = 可行 **且** 未在执行；改世界配置 = 来源合法 **且** 通过校验；保存场景 = 校验通过 **且** 写入成功 | `OrderService.StartOrder`、`WorkshopService.SetWorkshopCapability`、`/api/scenario` |
| 最小公共机制 | 共享状态只有一个闸门 `JarSystemService.Gate`，HTTP/WS/定时器共用；发送侧只有一个 `_sendGate` | `JarSystemService.cs`、`WebSocketHub.cs:25` |
| 心理可接受性 | 拒绝都要说人话：`订单 #3 正在执行中（过程 #12）：先取消过程，再删除订单` | 各处 `DomainValidationException` 文案 + 测试钉住 |
| 默认最小暴露面 | 6 个端点 + 1 个 WS，没有管理后台、没有调试端点；未使用的组件不注册 | `Program.cs` 全部 `Map*` 调用即完整清单 |

## 7. STRIDE 六类（本系统的实际形态）

| 威胁 | 本系统里的具体形态 | 现有控制 | 剩余风险 |
|---|---|---|---|
| **S**poofing | 伪造来源访问回环端口 | Origin + Host 双校验；仅 loopback 监听 | 本机其它进程可直连（OS 用户即身份边界，见 §11） |
| **T**ampering | 篡改世界状态/日志以骗过回放 | 状态只在服务端生成；命令日志 + 快照基线 + 逐字节回放 | 有心人可改代码后重跑门禁（构建未签名，§11） |
| **R**epudiation | 谁改了这个世界的配置 | 命令日志 `Record(WorldOps.*)` 记录配置变更；配置事件 `AddConfigEvent`；资源账本记录每个资源变化的唯一原因 | 无外部时间戳/签名 |
| **I**nformation disclosure | 页面或日志泄漏不该看到的信息 | 只发只读投影（DTO），`Jar` 全 internal；无堆栈回显（未知命令回一句话）；无令牌可泄漏（无令牌） | 本机进程可读内存 |
| **D**enial of service | 大量连接/超大请求体/超大配置 | WS 上限 8 → 429；请求体 1 MiB 上限（流式累计）；配置与关卡启动期校验 | 单线程串行闸门本身就是瓶颈（设计选择） |
| **E**levation of privilege | 页面绕过内核直接改世界 | 页面无状态写权限；所有改动都必须经命令 → 规则 → 日志；未知命令拒绝 | 无应用层身份，故谈不上越权（无权限模型） |

## 9. 供应链：依赖、SBOM、可复现构建

- **依赖现状**：`JarSystem.Core` 与 `JarSystem.Web` **零第三方包**；只有测试工程用
  `xunit.v3 4.0.1` 与 `FsCheck.Xunit.v3 3.4.0`（连同 18 个传递依赖）。
- **锁定**：版本写在 `.csproj` 里（具体版本，非浮动范围），SDK 固定在 `global.json`（若存在则以它为准）。
- **漏洞扫描**：`重构报告/security-gate.ps1` 第一部分，`High`/`Critical` 直接让 `VERDICT=FAIL`。
- **秘密扫描**：同一脚本第二部分（8 条保守模式，扫 410 个文件）。
- **SBOM**：`docs/security/SBOM.md`（随每次依赖变化手工同步；§11 记录"没有自动化生成"这个缺口）。
- **可复现**：`verify.bat` 每次都做 `--no-incremental` 全量重建，并把契约快照/回放字节与基线逐字节比对 ——
  产物的"同一性"在这里是可验证的，但**没有签名**。

## 10. 规则 → 证据索引（逐条）

> 说明：本仓库的威胁面很窄，"不适用"是结论而不是偷懒 —— 每处不适用都写明**为什么这条规则的前提在本系统里不存在**，
> 以及如果前提出现（比如将来加了账号体系），必须补什么。

### A 组：边界与授权

| 规则 | 状态 | 证据 / 不适用理由 |
|---|---|---|
| A-01 信任边界显式绘制 | 通过 | 本文件 §3 边界图 + §4 逐边界控制表 |
| A-02 权限判断收口单一入口 | 通过（自动） | 权限语义在本项目=`WorkshopRulebook.IsAllowed` + `CommandDispatcher` 白名单 |

| A-04 纵深防御 | 通过 | §5 表：每个资产 ≥2 层且机制不同（Origin vs Host、规则表 vs 求解器、快照 vs 回放） |
| A-05 不信任外部输入 | 通过 | §4 表；内网/本机来源同样校验（Origin 为空只用于非浏览器客户端，且有 Host 白名单兜底） |

## 10.5 权限点登记表（C-05）

**规则要求**：新增资源类型上线前必须显式登记权限点，登记表与资源类型一一对应。

**做法**：登记表住内核而不是宿主 —— `src/JarSystem.Core/Security/PermissionPoints.cs`
里有两张只读表，`Commands`（27 条）与 `Endpoints`（6 条），每条是一个
`PermissionPoint(Name, Category, Resource, Action, Why)`：**资源**（世界/工作台/订单/过程/时间/生产/关卡/作者数据）、
**动作**（读/写/创建/执行/切换/重置/重开/校验…）、**类别**（`BusinessRead` / `BusinessWrite` / `Admin`）、
**为什么需要它**。

宿主的两个入口都**先问表再执行**：

- `src/JarSystem.Web/CommandDispatcher.cs`：`PermissionPoints.TryFindCommand(type, out var point)` 失败 ⇒
  直接回 `未知命令`，不再落到 `switch` 的 `default`（HTTP 侧同理：`Program.cs` 的
  `POST /api/scenario` 先 `TryFindEndpoint("POST /api/scenario", …)`）。
- 未登记 = 拒绝（失败关闭）。新增一条命令却忘了登记，结果是"这条命令彻底不可用"，
  而不是"它绕过了权限检查"。

| 类别 | 命令（27） | 端点（6） |
|---|---|---|
| `BusinessRead` | `getState`、`getSteps`、`checkFeasibility`、`checkAllFeasibility` | `GET /api/state`、`GET /api/levels`、`GET /api/invariants`、`GET /api/scenario`、`POST /api/scenario/validate` |
| `BusinessWrite` | `createOrder`、`createRandomOrder`、`createWorkshop`、`createRandomWorkshop`、`updateWorkshopCapacity`、`setWorkshopCapability`、`moveOrder`、`setMaster`、`setSlave`、`executeOrder`、`deleteOrder`、`startOrder`、`cancelProcess`、`setTickInterval`、`manualTick`、`updateLiquidRate`、`updateProducerRate`、`startTick`、`stopTick`、`setAutoCheck` | — |
| `Admin` | `reset`、`restartLevel`、`loadLevel` | `POST /api/scenario`（写作者数据） |

**为什么管理类只有这四条**：它们能让**整局事实作废**（`reset`/`restartLevel`）或**换掉整个世界**
（`loadLevel`），以及把作者数据写进 `config/scenario.json`。其余 20 条写命令都只改"这一局里的东西"，
再糟也能用一条管理命令复原。

**守卫**：`test/JarSystem.Tests/SecurityPolicyTests.cs` 用**显式列表**（不是反射）钉住
"登记表 == 分派器的 case 集合""6 个端点齐全""Admin 恰好是 reset/restartLevel/loadLevel""未登记名一律拒绝"。
用反射会让"新增命令忘了登记"自动通过，那就白登记了。

## 10.6 管理接口与业务接口的分离鉴权（C-06）

**规则要求**：管理接口与业务接口必须分离鉴权策略。

**做法**：两类接口问的是**两套策略**，都在 `src/JarSystem.Core/Security/AccessPolicy.cs`：

```csharp
// 业务：只问"是不是本机"
// 管理：本机 + （配了 JAR_ADMIN_TOKEN 时连本机也要出示 X-JarSystem-Admin）
public static AccessDecision Decide(PermissionPoint point, AccessFacts facts, bool adminTokenConfigured);
```

| 主体 | 业务类别 | 管理类别 |
|---|---|---|
| 非回环地址（远程） | **拒**（`remote-denied`） | **拒**（`remote-denied`） |
| 本机、未配令牌 | 放行 | 放行（开发期零摩擦，行为可预测） |
| 本机、配了令牌、未出示 | 放行 | **拒**（`admin-token-required`） |
| 本机、配了令牌、出示且逐字相同 | 放行 | 放行 |

两条边界是刻意的：

1. **远程一律拒，哪怕出示了令牌。** 令牌回答的是"这台机器上是谁在操作"，不是"允许谁从外网连进来"。
   后者由 `JAR_ALLOW_REMOTE=1` 显式决定（见 §10.7），与令牌无关。
2. **未知来源（拿不到对端地址）一律拒**，连 `JAR_ALLOW_REMOTE=1` 也不放行 ——
   `HostPolicy.IsAllowedConnection` 先判 `remote != null`。放开远程表达的是"允许别的机器连"，
   不是"允许来源不明的连接"。

令牌的比较是 `StringComparison.Ordinal` 逐字比较，不做归一化、不 trim：管理令牌是人手配的开关，
"看起来一样"不算一样。连接上的两件事实在 `WebSocketHub` 握手时一次性取好
（`ConnectionAccess(IsLoopback, AdminToken)`），分派器只读不算。

## 10.7 宿主姿态：本机可及 + 低权限（G-06）

**规则要求**：服务必须以非 root 低权限账号运行，文件权限最小化。

三条落地（`src/JarSystem.Core/Security/HostPolicy.cs` 纯判定，`Program.cs` 只做取值与装钩子）：

1. **只服务本机**：`app.Use(...)` 中间件对 `Connection.RemoteIpAddress` 做判定，
   非回环直接 `403` 并留一行 `[security] 拒绝非本机连接: <addr>`。要开放必须显式设
   `JAR_ALLOW_REMOTE=1`（默认关闭）。这条与 §4 的 Origin 校验、Host 白名单、连接上限 8 是**四条独立防线**。
2. **提权告警**：启动时 `IsElevated()`（仅 Windows 判管理员令牌），为真则打印
   `HostPolicy.ElevationWarning(true)` 的中文告警到 stderr。**只告警不拒绝启动** ——
   开发机的 `dotnet run` 常年就在管理员终端里，拒绝启动只会让这条规则被人整段删掉；告警则让事实永远可见。
3. **文件权限最小化**：服务自身只写两个位置 —— 命令日志/过程日志（`config/` 旁的运行目录）
   与 `config/scenario.json`（固定路径、原子替换：先写临时文件再 `File.Move(overwrite: true)`，失败不留半截文件）。
   不接受外部传入的任意路径，不创建系统目录，不写注册表。

**为什么不内置"降权到某个账号"**：本壳由 `run.bat` 以**当前用户**前台启动，不以服务方式安装
（无 `sc.exe`/`systemd` 单元），因此"用哪个账号运行"由启动者决定，代码里硬编码账号名只会制造
一个看起来严格、实际绕得过的东西。真正的控制是上面三条：只接受本机、提权可见、写入面固定。

## 11. 已知缺口（不在正文里化妆）

| 缺口 | 为什么现在还这样 | 一旦前提变化必须补什么 |
|---|---|---|
| 无应用层认证 | 单机单用户，OS 账号即边界 | 引入远程访问/多用户时：会话 + 令牌可撤销 + 授权三元组 |
| HTTP 明文 | 只绑 loopback，无凭证可泄 | 对外暴露时：TLS ≥1.2 + HSTS + 证书固定（客户端） |
| 构建产物未签名 | 无发布仓库/商店 | 发布时：Sigstore / cosign + provenance attestation |
| SBOM 手工维护 | 依赖极少（产品零依赖），自动生成器会引入新依赖 | 依赖增长时：CI 内 `dotnet CycloneDX` 生成并归档 |
| 无真 fuzz | 关键解析面已被属性测试 + 差分测试覆盖 | 引入二进制协议/复杂解析器时：fuzz target |
| 无告警/响应流程 | 无值班体系 | 对外服务时：告警通道 + 责任人与响应 SLA |
| 管理令牌是明文环境变量 | 单机、进程私有环境，无跨机器传递 | 引入远程或多用户时：令牌改一次性签发 + 短期有效 + 可撤销 |
| 无应用层审计告警 | 无值班体系（§11 首行） | 对外服务时：管理命令写独立审计流并接告警 |
| Origin 为空即放行 | 非浏览器客户端（curl/测试）需要直连；Host 白名单兜底 | 若将来接受来自其它主机的请求：改为"必须带合法 Origin" |

## 12. 怎么复跑这些结论

```bat
rem 1) 全门禁（含依赖漏洞 + 秘密扫描）
set CI=1
重构报告\verify.bat

rem 2) 只看安全门（快，不跑测试）
powershell -NoProfile -ExecutionPolicy Bypass -File 重构报告\security-gate.ps1

rem 3) 只跑测试
dotnet run --project test\JarSystem.Tests\JarSystem.Tests.csproj -c Release
```

期望最后两行是 `SEC-OK (projects=5, vulnerable=0)` 与 `SEC-SECRETS-OK (scanned=N files, patterns=8)`，
并且 `VERDICT=OK`、`QUALITY-OK`、`REPLAY-OK (commands=33, stateBytes=4436, logBytes=8797, journalBytes=725)`。
