# 表现层框架：审计、结论、与已落地的接口

> 日期：2026-11　提交：见 `git log`（`JarSystem.Core/Presentation/` 首次出现的那一条）
> 关联：`CONSTRAINTS.md`（I2 断言/确定性、I4 契约同步）、`demo/过程呈现_设计.md`（demo 侧六层清单）

## 0. 一句话结论

**原系统没有表现层框架。** 它有两套**原语**（总线信号、过程日志），但没有一套"给外部世界看"的东西；
于是三个宿主各自造了一套词汇 —— Web 的 `ProcessObserver`（5 条消息）、demo 的 `G.events`（12 种 kind）、
以及录制/回放那一侧什么都不造。这不是重复劳动的问题，而是**契约不在核心里**：
谁也说不清"该来的都来了没有"。

本次落地的是一个**很窄**的框架（`JarSystem.Core.Presentation`，三件东西 + 一座桥），
它在结构上回答了"能不能装"：能，而且不需要改内核任何一条规则。

## 1. 审计：原有的是什么

| 界面 | 位置 | 它到底是什么 | 面向谁 |
| --- | --- | --- | --- |
| 总线 | `World/WorldBus.cs` + `World/WorldSignal.cs` | 粗粒度广播：`WorldChanged / ProcessChanged / TimePaused / TimeResumed`，带 `Tick` + `Revision`，**刻意不带载荷**（订阅方自己回查世界） | **世界内部**：反应器可借它引发级联（会改世界） |
| 过程日志 | `Process/Journal/ProcessJournal.cs` | append-only 追加、`seq` 单调、有界保留（满时成批丢最旧一半）、缺口可查（`DroppedEntries/FirstSeq/LastSeq/IsTruncated`） | **审计**：过程级步进 |
| 命令日志 | `JarSystem.CommandLog` | 世界级意图（`WorldCommand`），回放的唯一来源 | **回放** |
| 宿主的适配层 | `src/JarSystem.Web/ProcessObserver.cs`（`IWebSocketSink` 5 条消息）、`demo/puzzle_engine.js` 的 `G.events`（12 种 kind） | 各自翻译一遍 | **各自的屏幕** |

**关键判断**：前三条都不是"给表现层用的"——
总线允许订阅方**改世界**（表现层不该有这个能力）；过程日志是**步进明细**（不是时间线，也没有"一类变化"的词汇）；
命令日志是**意图**（不是发生的事，一次意图内部可能发生十几件事）。
而两个适配层证明缺口真实存在：**同一个世界，两套语义**。

## 2. 缺的是什么（四条，逐条对应一个后果）

1. **没有统一的顺序**：总线的分发顺序与世界发生的顺序一致，但没有任何东西把"信号"与"过程步进"排在同一条时间线上。
   ⇒ 宿主想看"先流入，再操作，再交付"，只能自己拼。
2. **没有帧号**：两条流各有自己的计数（`seq` / 无），谁也不知道"我漏了一条"。
3. **没有快照载体**：想让棋盘逐帧渲染，宿主必须自己抓状态（demo 就是这么干的：`benchSnap`/`worldSnap`）。
4. **没有节奏边界**：核心从不表达"这次推进有几步"，于是"播放"只能靠宿主猜。

## 3. 装的是什么（`src/JarSystem.Core/Presentation/`）

三件东西，刻意窄：

- `PresentationKind`：**封闭**词表（4 个值），与 `WorldSignalKind` 一一对应。
  封闭是刻意的 —— 表现层腐坏的方式从来不是画错，而是"每加一个功能就多一种消息"。
- `PresentationFrame`：`Seq / Kind / Op / Subject / SubjectId / Tick / Revision`。**只有引用，没有载荷**（与 `WorldSignal` 同一条理由：帧里一旦带状态就成副本，副本必然过期）。
- `PresentationFeed`：有界、`Seq` 单调、缺口可查（恒等式 `FirstSeq == DroppedFrames + 1`）、`Since(cursor)` 游标读取、`Subscribe(IPresentationSink)` 同步派发。
- 一座桥 `World/BusPresentationBridge`：**总线信号 → 帧**的唯一翻译点。
  它住在 `World` 侧而不是 `Presentation` 侧，是因为方向必须是这样：**是世界被投影成帧，不是帧去拉世界**（也让 `Presentation` 不必依赖上层，层序见 §5）。

## 四条承诺（都有测试）

| 承诺 | 测试 |
| --- | --- |
| 一帧一意图、顺序与命令日志逐条一致 | `PresentationFeedTests.EveryWorldChangedFrameMatchesOneCommandLogEntry` |
| 帧号连续、`Tick` 不回退 | `FramesAreSequencedAndTicksNeverGoBack` |
| 被裁剪后缺口可算（`FirstSeq == DroppedFrames + 1`） | `BufferIsBoundedAndReportsTheGap` |
| **挂不挂接收方，世界最终状态逐字节相同** | `PresentationDoesNotChangeTheWorldOutcome` |

最后一条是这套东西能进核心的唯一理由：帧流是**投影**，不是第二个真相。
删掉 `Presentation` 与那座桥，`REPLAY-OK` 四组字节不变 —— 本次门禁实测就是没变
（`commands=33, stateBytes=3146, logBytes=8797, journalBytes=725`）。

## 4. 为什么要"可安装"而不是"内建一套画面"

三条纪律写在类型注释里，也决定了它的寿命：

1. **核心不知道画什么**：帧里没有"罐子飞过去"这种东西，只有"谁、什么时候、哪一类"。动画属于宿主。
2. **节奏在宿主**：`Since(cursor)` 是拉模型；核心不睡眠、不排定时器、不知道你播多快。
   这与 `TickIntervalMs` 同类 —— "多久推进一次"从来是表现层参数。
3. **数据驱动落在宿主侧**：将来做"表现配置"（哪类帧配哪段动画、什么文案），配置文件读的是
   `PresentationKind` + `Op` + `Subject` 这三个**已有**字段，核心不需要为它加一个字段。
   —— 这正是"框架"与"现在能用"的分界：**词表稳定，映射可外置**。

## 5. 层序（写进 `ArchitectureTests`）

```
Config 0 · Domain 1 · Abstractions 2 · Presentation 3 · Rules 4 · Production 5 ·
Solver 6 · Commands 7 · Orders 8 · Process 9 · Services 10 · Sessions 11 ·
Executor 12 · World 13 · Bootstrap 14
```

`Presentation` 与 `Abstractions` 同类（纯契约 + 有界缓冲，不依赖任何层），排在第 3 位。
规则仍是一句：**只许引用排位更低的层**。`World(13) → Presentation(3)` 因此合法，
而"让 `PresentationFeed` 自己订阅总线"（`Presentation → World`，向上）会被这条测试直接打回。

## 6. 还没做的（诚实清单）

- **帧里没有中间态**。棋盘逐帧渲染靠的是宿主自建读模型（demo 的 `snap`）；
  核心不承诺"第 k 帧的世界长什么样"。要不要把快照纳入契约，是一个需要单独论证的变更
  （代价：每帧一份状态，长跑必爆）。
- **过程步进还没进帧流**。`ProcessJournal` 仍是独立的一条；把"某订单第 2 步"做成帧，
  需要先回答"它属于哪一类" —— 我倾向新增 `PresentationKind.ProcessStep`，但那会让帧种类变成 5 个，
  等有第二个宿主真的需要时再做。
- **Web 宿主还没切过来**。`ProcessObserver` 仍在用自己的 5 条消息。
  切换的成本很低（它已经只做翻译），但会动协议面（`PROTOCOL-OK` 的 16 条消息），
  按 I4 需要一次显式变更。
- **demo 还没切过来**。demo 的 `G.events` 里有 12 种 kind，粒度比帧细得多
  （`op` 带 from/to 形状）。它其实是"帧 + 宿主自己的细节查询"的组合，
  切换需要先把细节查询这条路铺好（见第 1 条缺口）。

## 7. 这次审计的教训

审计的触发点不是"我们缺个框架"，而是**两个宿主的行为对不上**。
所以先做的是**清点已有界面**（第 1 节的表），再判断缺的是哪一层。
如果我上来就设计"事件总线 2.0"，一定会把总线已经解决的"可反应、可级联、可复现"重新发明一遍，
并且忘掉它最要紧的那条性质：**订阅方允许改世界**。表现层恰恰不该有这个能力。
