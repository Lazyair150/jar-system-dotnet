# 陶罐系统完整规则文档

## 1. 工作台标记转换规则

| 罐子形状所在标记 | 可转换为 |
|-----------------|---------|
| 在基础标记中 | 所有其他基础标记 + 所有附加标记 |
| 在附加标记中 | 所有基础标记（不能转为其他附加标记） |
| 不在任何标记中 | 所有基础标记 |

## 2. 倒液规则 (PourIn)
- 罐子必须为空 + 形状必须是基础标记 + 液体不得被禁 + 液体库存 >= 1
- 消耗: 液体 -1

## 3. 改形规则
- 空罐改形: 罐子为空 + 可转换 + 消耗1份成本液体
- 满罐改形: 罐子为满 + 可转换 + 罐内液体不被禁 → 清空罐内液体，形状改变

## 4. 禁令规则
- 工作台可禁酒或禁蜜
- 被禁的液体：**可以存储**（能流入、能留在池子里、能随罐子转移），但不能倒入罐子、不能做成本液体
- **禁液令不影响存储与转移**：装满被禁液体的罐子仍可正常持有、转移、回滚、被其它工作台接收；
  游离的禁液也可以流进工作台并留在池子里（那一格仍然存在）；
  禁令只作用于「倒入空罐、改形成本、满罐自耗」——即**取用**，不含存储

## 5. 订单规则
- A类：主台独立完成，无转移
- **主台 / 从台的位置职责不同**：主台与仓库管道齐平，是仓库资源的唯一接收方；从台是 B 类订单执行时临时升起的工具位，不是第二仓库
- **从台必须是空的**：有罐子或液体的工作台不能被选为从台；B 类订单开始时也再次校验这一前提
- B类：主台预处理 → 选择性转移（只转移「交付罐 + 从台阶段计划使用的工具罐」，其余留在主台）→ 从台继续 → 从台交付
- B类液体：只转移从台阶段实际需要的量
- **B类收尾排空从台**：交付罐先移除；从台剩余的所有罐子与游离液体全部回流主台。游离液体包括工具罐倒出后未被消耗的部分，不能只按“转入液体”账目返还
- **从台残留是错误状态**：B 类终态后从台必须为空；无运行中的 B 类订单时，已选从台仍有资源即违反世界不变量
- 订单需求数量上限：10 个（用于约束可行性分析的搜索规模；注意 2^N 划分搜索只是其中一维，
  真正的成本还随「池子罐子数」指数放大 —— 实测 8~10 需求且**不可行**的 B 类订单会超出分析预算）
- **中央仓库单向流动**：资源只从仓库流向工作台；工作台容量溢出与回滚溢出的资源直接丢弃（计入丢弃计数），不回收
- 需求列表展示约定：空罐需求在前、满罐需求在后（仅列表排版约定；实际执行顺序为满罐优先，见第 6 节）
- **失败要付代价（设计定案，2026-09 确认）**：订单执行失败时，**主台上已经发生的操作不回滚** ——
  已改形的罐子保持新形状、已消耗的成本液体不返还、已倒出的液体留在工作台（操作标记会被清除）。
  从台剩余物仍会全部回流主台（未交付罐子、工具罐与全部游离液体），
  回流途中的容量溢出**直接丢弃**（同"单向流动"；禁液仍可存储，不受影响）。
  ⇒ 试探一个订单本身有成本，这是 puzzle 的一部分，**不要**当缺陷修掉。
- **可行性分析的"未判定"**：需求多（尤其 B 类）时搜索可能超出预算，此时给出的是
  **`undetermined`（未判定）**，而不是"不可行"。两者必须区分：只有"确实不可行"才受
  「判定不可行 ⇒ 执行必失败」这条不变量约束；未判定的订单仍可直接执行（由贪心兜底）。

## 6. 执行规则
- **交付是原子事实**：当交付资源形状正确、数量正确、位置正确时，一次性完成全部交付；不存在“逐只交付”的 tick 过程
- **MATCH 不是实现动作**：MATCH 只表示可行性匹配与交付预留，不占用过程单位，也不因直接匹配而等待回合
- **只有实现过程 tick 驱动**：POUR_IN / POUR_OUT / RESHAPE / 主从 TRANSFER 等改变资源位置或形态的操作才占用过程单位
- **A 类直接交付**：订单开始时主台已经满足交付，开始订单即完成，不要求额外推进一回合
- **B 类迁移是一步**：多个必要罐子和液体作为一个多目标迁移单位执行；迁移完成且从台交付成立时，在同一单位结束时一次性交付
- **默认一回合一单位**：每次手动推进完成该回合所有到期的世界阶段，并推进当前过程的一个实现单位；
  默认不存在“隔一回合才执行下一步”的等待。只有显式 `ticksPerStep` 或 `Retime` 修饰器才能让某过程跨多回合
- 满罐需求优先于空罐需求
- isMarked标记防止同一罐子被多次操作
- **切换主台**：旧主台资源通过临时传输规则迁往目标工作台；切换过程存在时关闭主台仓库接收入口，完成后从下一个 tick 恢复
- **无资源切换**：旧主台为空时可直接切换指针，不启动搬运过程
- **过程互斥**：订单执行与主台切换不能并行；主台切换期间不能启动新订单
- **活动订单冻结位置**：订单过程存续期间，主台/从台指针只能保持原值，不能通过同步或裸索引入口改变

## 7. 满罐需求限制（设计说明）
- 一罐一操作：同一订单执行中每个罐子最多被操作一次
- 因此满罐需求只能由「现成满罐」或「现成同形空罐 + 倒入液体」满足；改形只能服务于空罐需求
- **设计定案（2026-08-01 确认）：不放宽**。该限制是当前规则组合的隐含结论，也是刻意保留的 puzzle 约束；
  若未来改变主意，需同步修改求解器与执行器并回归全部测试
