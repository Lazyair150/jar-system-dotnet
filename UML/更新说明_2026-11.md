## 1. 结论先说

旧图停在 2026-10-16。此后代码在两处发生了**结构性变化**，旧图不是"少画了几个类"，而是**结论错了**：

| # | 旧图的说法 | 现在的事实 |
|---|---|---|
| 1 | 分层是"包 + 两处味道"（Domain→Services、Abstractions↔Solver/Orders） | 分层治理后层序为 L0 Config … L13 Bootstrap 一条链，**双向环 7 → 0**，两条味道**都不存在** |
| 2 | `RuleContext` / `ModifierStack` / 5 种 Modifier 属 Rules 层 | 已**下沉到 Domain**（它们描述"工作台当前生效的法则"） |
| 3 | `IIdGenerator` / `DefaultIdGenerators` 在 Services | 已**下沉到 Domain** |
| 4 | `Requirement` / `JarState` / `SolverResult` / `WorkshopInfo` 在 Solver·Orders | 已统一到 **Abstractions** |
| 5 | 换台 = 一条同步链路 | 它是一个**过程**：`Begin → RunReshape → RunTransfer`，一 tick 一段，可失败、可取消（取消要回滚），与订单执行互斥 |
| 6 | 没有世界总线 / tick 阶段表 / 统一逻辑时间 | `World/` 与 `Process/Scheduler/` 是整块新设施 |

## 3. 未做的、以及为什么

1. **07/13/14 三张没有做渲染验证**：本机只有 JVM，没有 `plantuml.jar`。语法按常见写法写，
   但"能渲染"这件事我没验证过，**不能声称已验证**。请在 VS Code 预览；报错行号发我。
2. **`02_ClassDiagram` 没有重画**：它 34KB、由逐类型手写而成。重画的收益是"新类出现在正确位置"，
   风险是把一张已经正确的图改坏。因此选择**补注 + 指路**（新增类型清单 + 指向 13/14）。
   若你要的是"一张完整的当前类图"，那是一次独立任务，可以重生成。
3. **没有画 Web / Godot 宿主内部**：`04_Component_模块边界` 已覆盖"多宿主 + contract-first"的边界，
   宿主内部实现属另一个关注点，未展开。
4. **demo 原型完全不进图**（按你的限定）。
