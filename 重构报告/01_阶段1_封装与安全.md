**批 3 的等价性论证**

1. **Undo 修正**：`Execute` 后状态为「罐满 + 已标记 + 库存 N−1」。`Unmark()` → `PourOut`（要求未标记、非空、未禁、存储未满，均成立）→ 罐清空 + 库存回 N + 重新标记 → 再 `Unmark()` ⇒ 与 `Execute` 前完全一致。原实现两处错误：未清标记即 `PourOut`（必失败）+ 成功后重复返还 1 单位。**因原方法在运行期不可达（审计 §2.10 已溯源到 Node 原版），本修正不产生任何可观测行为变化**。
2. **死字面量删除**：`"combined_under_slave"/"two_phase_simulation"` 在任何代码路径都不会写入 `CheckMethod`（`CheckTypeB` 只产出 `slave_only`/`partition`，`CheckTypeA` 只产出 `single_phase`）。
3. **`FlowToMaster`**：原 `-= amount` 后在两个拒绝分支 `+= amount`（净 0）、成功分支 `+= amount - accepted`（净 −accepted）→ 新实现按 `accepted` 直接相减，三条路径净效应逐一相同。
4. **魔法字符串常量化**：全部为 `const string` 同值替换，JSON 输出字符串与判定结果不变。
5. **订单状态机封装**：新增方法体即原来的赋值语句，值不变；`Requirements`/`Type` 原本只在构造函数写入。

**批 3 有意未做（留给阶段 2/3，已在 §6 记录）**：solver 操作类型字符串（`MATCH/POUR_IN/POUR_OUT/RESHAPE`）常量化；`Order.Requirements` 改 `IReadOnlyList` + 拷贝；`Workshop` 的标记/容量可写与 Case2 临时标记作用域化；`FeasibilityChecker.IsBanned` 去重；`Jar.NextId` 静态 ID 注入化。
