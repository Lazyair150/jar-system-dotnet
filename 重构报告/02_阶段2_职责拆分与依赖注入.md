| `Web/JarSystemService.cs`（新） | 组合根（系统实例 + 闸门 + 两个定时器）；删除因迁移而失效的 `Clients` 字段 |
| `Web/Program.cs`（重写） | 205 行 → 39 行：`AddSingleton` + `/api/state` + 静态文件 + `/ws` 中间件委派 + `app.Run()` |

**等价性论证（2F）**

1. **命令与消息契约逐字保留**：19 个命令名、9 种消息名、每个 payload 的键集合与产生顺序、错误消息文案（"订单不存在"/"切换失败"/"设置从台失败"）全部照搬；`setMaster` 的 `workshopSwitched` 分支条件、`checkFeasibility` 的 `orderId` 解析、`ResolveOrderIndex` 的 `orderId` 优先/`orderIndex` 兼容顺序均未改动。
2. **闸门语义一致**：`CommandDispatcher.HandleAsync` 与两个定时器回调、`/api/state` 仍共用 `svc.Gate`（`SemaphoreSlim(1,1)`），进入/释放时机与重构前相同（定时器是「取闸 → Tick/分析 → 释放 → 广播」）。
3. **JSON 序列化一致**：`JsonArgs.Options` 与原 `jsonOpts` 相同（camelCase）；`J(object)` 签名不变，故匿名类型仍按运行时类型序列化。
4. **传输语义一致**：`SendAsync` 在连接非 Open 时不发送、发送异常写 stderr；广播仍是「快照遍历 → 存活者发送 → 收集死连接 → 统一移除」；会话收尾仍是「移除注册 → 尝试正常关闭（失败忽略）」。
5. **`/ws` 中间件判定不变**：`Path == "/ws" && IsWebSocketRequest`，否则 `next(ctx)`。
6. **可测性提升**：`IWebSocketSink` 让分派器可在无真实 WebSocket 的情况下做单元测试（阶段 3 可补）。

**阶段 2 完成情况**：2A ✅ 2B ✅ 2C ✅ 2D ✅ 2E ✅ 2F ✅。五个 God class 全部拆分完毕（`JarSystem` 328→119 行、`OrderExecutor` 390→165 行、`FeasibilityChecker` 321→215 行、`WorkshopSwitchEvent` 301→68 行、`Program.cs` 205→39 行），并引入 5 个接口（`ISolver`/`IIdGenerator`/`IJarSelectionStrategy`/`ISystemLog`/`IWebSocketSink`）。

## 0. 阶段目标

审计结论是「骨架对、抽象层缺」。阶段 2 只做两件事：

1. **拆分 5 个 God class**，让每个类只有一个变更理由（SRP）。
2. **引入最小接口集 + 构造函数注入**（DIP），使协作对象可替换、可测试，且保持 `new JarSystem()` 零参数可用（默认装配，不引入 DI 容器）。

**不做**：不改规则、不改 JSON、不引入 DI 容器/仓储/工作单元、不引入异步/事件总线（Observer 属阶段 3）。

## 3. 最小接口集（阶段 2 引入，共 4 个）

```csharp
public interface ISolver
{
    SolverResult Solve(List<Requirement> requirements, WorkshopInfo workshopInfo,
        List<JarState> jars, Dictionary<string, int> liquids, int transferBudget = int.MaxValue);
}

public interface IIdGenerator { int Next(); }                  // Jar / Order 共用，默认进程内单例实现

public interface IJarSelectionStrategy                        // 阶段 3 落地 4 个实现
{
    Jar? Select(IReadOnlyList<Jar> candidates);
    string Name { get; }
}

public interface ISystemLog { void Error(string message, Exception? ex = null); void Info(string message); }
```

**注入策略**：全部走构造函数，带默认值（`IIdGenerator? ids = null` → 默认共享单例），
`JarSystem()` 无参构造仍然可用且行为不变；Web 层与测试工程无需改动即可编译。

**`IIdGenerator` 落地细节**：`Jar.NextId()` 静态门面保留但标记 `[Obsolete]`（避免外部编译中断），
`Workshop.AddJar` 与 `Order` 构造函数改为从注入的生成器取号；默认实现保持「进程内单调递增、`Reset()` 不清零」的现有语义。
