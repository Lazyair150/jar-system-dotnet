# 05 扩展指南 —— 想加东西时该改哪里（含安全边界）

> 用途：回答"我要加一个新形状/新液体/新工作台/新策略/新检查/新命令，需要动哪些文件、不能动什么、怎么验证"。
> 读取时机：**只在真的要扩展时才读本文**；只做维护/重构不必读。
> 所有结论均来自当前代码实读（文件:行），不是设计愿景。文末 §9 列出"扩展前必读的硬约束"。

---

## 0. 一句话总览：三类改动，代价完全不同

| 类别 | 例子 | 代价 | 原因 |
|---|---|---|---|
| **数据型扩展**（只加数据，不加规则） | 新工作台模板、新生产者、新生产者速率 | **极低**：1 处数据 + （可选）1 处装配 | 规则由"标记"派生，不写死在代码里（见 §1） |
| **策略型扩展**（加一个实现类） | 新罐子选择策略、新可行性检查、新切换分支 | **低**：1 个新类 + 1 处注册；不动既有逻辑 | 阶段 3 已把这三处做成 Strategy / 责任链 / 分支策略 |
| **语义型扩展**（改动"域"本身） | 新形状、新液体、新订单类型 | **中～高**：核心 1～2 处 + **前端副本** + 契约风险 | 形状/液体在前后端各有一份清单（§4）；订单类型会被写进 JSON 的 `type`（§6） |

## 1. 先理解"形状转换规则"是派生的，不是表

`Config/Rules.cs:31-48` 的 `ShapeRules.GetPossibleTransforms(baseMarks, additionalMarks, shape)` 是**唯一实现**，规则如下：

- `shape ∈ 基础标记` → 可变成「其它基础标记 + 全部附加标记」
- 否则（附加标记 / 无标记）→ 可变成「全部基础标记」

**推论（重要）**：
1. **没有**"圆罐只能变方罐"这类硬编码配对表 —— 转换能力完全由工作台的 `baseMarks/additionalMarks` 决定。想改变某台的转换能力，改它的**标记**即可，不用改代码。
2. 新增形状**不需要**改规则引擎；只有在你想给某台"授予"该形状的转换能力时，才把它加进该台的标记。
3. 引用者只有 3 个，且全部委托到这里（`Workshop.GetPossibleTransforms`、`Solver.WorkshopInfo.GetPossibleTransforms`，见 `Domain/Workshop.cs:87`、`Solver/StateSpaceSolver.cs:67`）—— **不要**在任何地方复制这段逻辑（审计记录显示历史上曾有三份拷贝并漂移过）。

### 3.2 新增"可行性检查"（责任链）

| 步骤 | 文件 | 改动 |
|---|---|---|
| 1 | `Orders/Feasibility/FeasibilityChecks.cs:14` | 读 `internal interface IFeasibilityCheck { FeasibilityResultData? TryCheck(FeasibilityContext ctx); }`（返回 `null` = 不适用，交下一环） |

⚠️ **顺序敏感**：链序即优先级，`PartitionCheck` 是兜底（2^N 搜索，最贵）。新检查若比 `PartitionCheck` 更便宜，插在它**之前**；若是"特殊快速路径"，插在最前。
⚠️ `IFeasibilityCheck` 是 `internal`：**外部程序集无法实现**。要让插件式检查可用，需先把它改 `public`（属 API 变更，需评估）。
⚠️ 结果对象必须经 `FeasibilityResultFactory` 拼装（`CheckMethod` 常量在 `Config/Constants.cs:47-52`），不要在检查里手写字段名。

## 4. 语义型扩展：新增形状 / 新增液体（**代价最高，涉及前端副本**）

### 4.1 后端权威清单（2 处）

| 文件 | 内容 |
|---|---|
| `Config/Constants.cs:7` | `SHAPES = [...]`（8 个） / `:8` `LIQUIDS = ["酒","蜜"]` |

改这里会**立即影响**：
- `Order.ValidateOrder` 的域校验（非法形状/液体被拒，见阶段加固 F）

- `--dump-contract` 契约快照的键集合

### 4.2 前端**字面量**清单（必须同步，否则 UI 缺项）

> ⚠️ **形状/液体"清单"已不再由前端维护**：`wwwroot/js/constants.js` 已删除，需求下拉框、标记选择器、
> 禁令选择器一律消费后端 `world` 消息下发的 `worldMeta`（`app.js:18,161` → 渲染于 `:318,335-337`；
> `index.html` 已无副本）。下表只剩**液态字面量与配色**这一类债务。

| 文件 | 内容 | 不同步的后果 |
|---|---|---|
| `wwwroot/js/app.js`（`:207-208` 禁令判定、`:216/:233-234` 库存与配色类、`:281-282` 仓库计数） | 液体的字面量 `'酒'`/`'蜜'` 与 CSS 类 `jar-full-wine`/`jar-full-honey` | 新液体在 UI 里**没有自己的颜色**：`j.liquid === '酒' ? 'wine' : 'honey'`（`:230`）会把任何非酒液体渲染成"蜜"色；禁令栏与库存栏也不显示该液体 |
| `wwwroot/css/*` | `.jar-full-wine` / `.jar-full-honey` / `.liquid-wine` / `.liquid-honey` 样式 | 同上，缺样式 |

> **结论**：新增液体的成本**已从"清单"转移到"配色与文案"** —— 清单由后端 `world` 消息下发（已落地），
> 后端本身仍只有 1 行；剩下的"前后端字面量重复"债务是 `app.js` 里的 `'酒'`/`'蜜'` 判定与 CSS 类名。
> **建议的下一步**：让 `worldMeta` 连液态**色值或索引**一起下发，前端按索引取色（不再按名字分支），
> 这样加液体就真的只需改 `Config/Constants.cs`。

### 4.3 新增形状的额外检查项

- 形状**不需要**在 `ShapeRules` 里登记（§1）。
- 但新形状若从未在任何台的标记中出现，它**只能作为初始罐子存在**，无法被"改形"产出 —— 这是规则的必然结果，不是 bug。
- `ProducerModule` 的 `Generators` 按形状懒建（`ShapeProductionLine`），新形状只要有生产者就会自动出现（`ProducerModule.cs:45-57`）。

实现方约定：**不得抛异常、不得反向调用 `JarSystem`**（见接口文档）。

## 8. 安全边界现状（扩展时不要踩坏）

已在阶段加固 F 落地的（`Web/WebSocketHub.cs`、`Web/CommandDispatcher.cs`、`Web/Program.cs`、`run.bat`）：

| 项 | 现状 | 扩展时的注意 |
|---|---|---|
| 绑定地址 | 默认 `http://127.0.0.1:3457`（**仅回环**） | 这是**主要防线**。改成 `0.0.0.0` 前必须加鉴权，见下 |
| Origin 校验 | 拒绝非回环 Origin（CSWSH 防护）；**允许无 Origin 的客户端** | 非浏览器客户端（脚本/爬虫）可绕过 Origin 检查 —— 所以回环绑定不可去掉 |
| 并发连接 | 上限 8，超出 429 | 若做多用户要重新设计闸门（`SemaphoreSlim` 是**单用户**语义） |
| 报文 | 上限 32KB，拒绝分片 | 新命令若传大 payload 会被直接断连 |
| 入参校验 | 形状/液体域、订单类型 A/B、容量非负 | 新命令**必须**沿用"非法 → `{type:"error"}` 且不动状态" |
| 进程管理 | `run.bat` 不再 `taskkill /f /im dotnet.exe` | 不要加回全局 taskkill |

**尚未做（若越过本机回环就必须做）**：
1. **无鉴权**：任何能访问该端口的人都能操作整个系统（`reset` 会清空世界）。局域网/公网暴露前必须加 token（首连接握手校验）或反向代理层认证。
2. **无每连接速率限制**（只有连接数上限）。
3. **无 TLS**（本地演示够用；跨机必须 HTTPS/WSS）。
4. **审计文件**：批 A 已把 `ISystemLog` 接到 Core（默认写 stderr），但它只覆盖"否则会丢"的诊断；**要留审计文件**需宿主注入自己的实现（写文件/采集器），并在 `Program.cs` 里 `new JarSystem(myLog)`。

## 9. 扩展前必读的硬约束（违反即违约）

1. **JSON 契约冻结**：`GetState()` 全字段 + 路径步骤 14 键（`step/requirement/operation/type/jarIndex/jarId/jarShape/jarLiquid/targetShape/targetLiquid/costLiquid/reshapeMode/consumed/jarsAfter`），由 `Services/StateDtos.cs` 的 `[JsonPropertyName]` 钉死；前端 `app.js` 依赖。
2. **WS 命令/消息名 + payload 键冻结**（`Web/CommandDispatcher.cs`）。
3. **测试基线**：`0 bugs / 2000 random + 0 bugs / 3000 capacity + 22 deterministic`（S1–S22）必须保持。
4. **规则语义**：一罐一操作、禁令不影响满罐转移、满罐需求不放宽、选择性转移、溢出**丢弃不回收**。
5. **`JarState.Copy(source, bool? masterOrigin = null)`** 必须保持 `MasterOrigin` 默认语义（影响转移预算判定）。
6. 改完**必须**由用户执行：
   ```bat
   cd /d D:\codex\jar-system-dotnet
   重构报告\verify.bat
   ```
