# 09 调研：宿主与配置（泛型主机 / DI / 日志 / 配置外置）

> 状态：**调研报告（未改动任何代码）**
> 范围：`Bootstrap/SystemBootstrapper.cs`、`Config/Constants.cs` + `Config/Rules.cs`、`JarSystem` 手写构造注入、
> `Abstractions/ISystemLog.cs` + `Services/ConsoleSystemLog.cs`、`Web/Program.cs`（minimal API）。
> 方法：`web_search` / `web_fetch`，链接见文末（区分官方 / 社区）。
> 正文约 800 字；目录结构建议与链接列表为附加内容。

---

## 结论（TL;DR）

核心库**不引** hosting：容器只在宿主层，核心保持 `new JarSystem()` 可用。
迁移分三段 —— **宿主层 DI → 日志 → 配置外置**，每段都保持对外 JSON 契约不变、可独立 revert。

---

## 1. 泛型主机与 DI（官方）

`IHostApplicationBuilder`（`Host.CreateApplicationBuilder`）是 .NET 6+ 的推荐写法，`WebApplicationBuilder` 是其 Web 变体；
`Build()` 后自动提供 `IHostApplicationLifetime` / `IHostEnvironment` / `IHostLifetime`。

**规范结构**：核心库只引 `Microsoft.Extensions.DependencyInjection.Abstractions`（加 `Options`），
并暴露 `AddJarSystem(this IServiceCollection, IConfiguration? section = null)`；Web / CLI / 测试各自 `AddSingleton`，
Godot 手动建 `ServiceCollection`（Godot 没有 ASP.NET 式宿主，社区用 AutoInject 一类方案）。

这与官方"库作者 Options 指南"的**默认值 + 可覆盖**模式一致：
把 `SystemBootstrapper` 的手写装配降级为 `JarSystemOptions` 的 `Configure(默认值)`，
于是 `new JarSystem()` 仍走同一套默认（无 DI 也能用），DI 只是第二条入口 —— 这正是"核心不依赖 DI 包"的规范答案。

**Godot 注意**：Godot 4.4+ 最低 net8.0；若 Godot 宿主仍 target `net8.0`，核心库需多目标 `net8.0;net10.0`
（另有 Godot 4.5-mono 在 .NET 10 下的共享框架探测问题已报 issue）。

## 2. 日志

换 `ILogger<T>` 收益：结构化字段（可查可聚合）、级别过滤、Provider 生态、`LoggerMessage` 源生成
（零装箱、低分配、编译期诊断）、OTel / 文件 / Godot 转发都是现成的。
代价：核心多一个 `Logging.Abstractions` 依赖，且日志必须写成 message template。

**推荐**：核心只依赖 `ILogger<T>` 抽象；`ConsoleSystemLog` 降级为一个 `ILoggerProvider` 适配器保留一版；
Godot 宿主写 Provider 转发到 GD.Print / 日志面板。
**不推荐**在"需要零依赖或给非 .NET 方调用"时强上 `ILogger` —— 那种场景自定义 1–3 个方法的 `ISystemLog` 更合适。
本项目以 Web 宿主为主，建议迁。

## 3. 配置外置（规则表）

用 JSON：`appsettings.json`（宿主级）+ `rules.json`（形状 / 液体 / 工作台模板 / 转换规则），
走官方 `Microsoft.Extensions.Configuration` + Options。**校验三层**：

| 层 | 手段 | 用途 |
|---|---|---|
| 字段级 | `ValidateDataAnnotations()` | `[Required]` / `[Range]` |
| 类级 | `IValidateOptions<T>` | 跨字段、引用完整性、模板重名 |
| 时机 | `ValidateOnStart()` | **启动即失败**，而不是首次下单才炸 |

集合/嵌套要显式递归：`[ValidateEnumeratedItems]` / `[ValidateObjectMembers]`（默认不递归）。
`JsonSchema.NET` 适合 CI / 策划侧预校验，代价是 schema 与 C# **双份维护**；YAML / TOML 需社区 Provider。

**行业实际**：游戏 / 模拟项目更常用 Excel → 代码生成（Luban 类工具链，产出 C# + JSON/BSON），
因为策划要改数值、CI 要生成。规则表规模小（本项目 8 形状 / 2 液体 / 数个模板）则纯 JSON + Schema 足够。
**注意**：`Constants` 里的 `OrderPhase`、`CheckMethod`、`SwitchCaseType` 等字符串是**输出契约**，不要配置化。

## 4. 后台服务与定时器

官方示例即 `BackgroundService` + `PeriodicTimer`：`while (await timer.WaitForNextTickAsync(ct))` ——
天然串行、**不会重入**；而 `System.Threading.Timer` 文档明示**不等待上次执行完成**。坑：

1. .NET 6+ `ExecuteAsync` 未捕获异常 → 默认**停主机**（可设 `BackgroundServiceExceptionBehavior.Ignore`）；
2. `ExecuteAsync` 首段同步阻塞会拖住主机启动 —— 要尽快 `await`；
3. `StopAsync` 默认 30s 超时，超时后强杀（`HostOptions.ShutdownTimeout` 可调）；
4. 长任务挂 `IHostApplicationLifetime.ApplicationStopping`，别用 `Environment.Exit`；
5. Hosted Service **默认没有 scope**，需要时自己 `IServiceProvider.CreateScope()`。

## 5. 迁移顺序（每步可 revert）

| 阶段 | 动作 | 验证（契约不变） |
|---|---|---|
| P1 | 新建 `JarSystem.Hosting`（核心零改动）→ `AddJarSystem()` + Web 改 `WebApplicationBuilder` | `WebApplicationFactory` + Verify 快照逐字节比对 HTTP / WS JSON |
| P2 | 日志换 `ILogger<T>`（保留 `ISystemLog` 适配器一版，可灰度回滚） | 既有日志断言 / stderr 基线不变 |
| P3 | 规则外置 `rules.json` + Options 校验 | 黄金用例哈希回归（4 生产者 / 6 工作台 / 可行性结果） |

**不值得迁**：核心库引 Hosting 或 DI 容器；`JarSystem` 内部持有 `IServiceProvider`；
`Constants` 输出契约字符串配置化；给 Godot 宿主强套 Generic Host（无 host、无收益）。

## 6. 目录结构建议

```
src/JarSystem.Core              零 hosting 依赖（可选：Logging/DI Abstractions）
src/JarSystem.Hosting           AddJarSystem() / JarSystemOptions / IValidateOptions
src/JarSystem.Web               WebApplicationBuilder（现状 src/JarSystem.Web）
src/JarSystem.Cli               Host.CreateApplicationBuilder
src/JarSystem.Godot             ServiceCollection + AutoInject（宿主自建）
config/rules.json + rules.schema.json
test/JarSystem.Test             黄金用例回归
test/JarSystem.Web.ContractTests WebApplicationFactory + Verify 快照
```
