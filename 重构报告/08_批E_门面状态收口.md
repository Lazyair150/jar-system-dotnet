## 1. 为什么要收口：一个真实可构造的非法状态

改前门面的状态成员全是 `{ get; set; }`，外部可以直接：

```csharp
sys.Workshops.Clear();     // 工作台没了
sys.CurrentMaster = 5;     // 索引仍指向 5
sys.GetState();            // 或 ExecuteOrder / Tick → Workshops[5] → IndexOutOfRangeException
```

也就是说，"世界的形状"和"主从选择"这两个必须保持一致的量，**没有任何地方强制它们一致**。
审计里 H1 记的就是这件事，也是这批加固里唯一涉及"外部可见 API 形状"的一项。

## 2. 收口映射（旧写法 → 新写法）

| 旧写法（公开可写） | 新写法（命名意图方法） | 说明 |
|---|---|---|
| `sys.Workshops.Add(w)` | `sys.AddWorkshop(w)` | 语义不变 |
| `sys.Workshops.Clear()` | `sys.ClearWorkshops()` | **附带**把主/从选择清空，杜绝遗留越界索引 |
| `sys.Orders.Add(o)` | `sys.AddOrder(o)` | 语义不变 |
| `sys.Orders.Clear()` | `sys.ClearOrders()` | 语义不变 |
| `sys.CurrentMaster = i` | `sys.SetMasterIndex(i)` | **裸选择**：不触发切换事件（区别于 `SetMaster(i)`，后者会按规则搬运资源）；越界即抛 `ArgumentOutOfRangeException` |
| `sys.CurrentSlave = i` / `= null` | `sys.SetSlaveIndex(i)` / `SetSlaveIndex(null)` | 同上 |
| `sys.ProducerModule = new ProducerModule()` | `sys.ResetProducerModule()` | 语义不变（旧仓库内容丢弃） |
| `sys.LiquidProductionRate["酒"] = 0` | `sys.SetLiquidProductionRate("酒", 0)` | 该字典**不参与 JSON 契约**，现改为 `IReadOnlyDictionary` |
| `sys.FlowSettings = (3, 2)` | `sys.SetFlowSettings(3, 2)` | 同上 |

**只读化（对外）**：`Workshops` → `IReadOnlyList<Workshop>`、`Orders` → `IReadOnlyList<Order>`、
`EventHistory` → `IReadOnlyList<Dictionary<string, object?>>`、`LiquidProductionRate` → `IReadOnlyDictionary<string, int>`。
**不可再整体替换**：`ProducerModule`（`private set`）、`Checker`、`Executor`（`{ get; }`）、
`CurrentEvent`/`CurrentMaster`/`CurrentSlave`/`AutoCheckEnabled`/`FlowSettings`（`internal`/`private set`）。

**服务层通道**：`WorkshopService`/`OrderService` 通过程序集内视图 `WorkshopList`/`OrderList`/`EventHistoryList` 修改
（`internal` ⇒ 外部程序集看不到，服务层不必互相绕过门面）。

### 保留的注入点（刻意不收）
| 成员 | 为什么保留 |
|---|---|
| `Checker`（`FeasibilityChecker`） | 可通过其构造注入 `ISolver` 替身做测试；整体替换无用例，故只读 |
| `Executor`（`OrderExecutor`） | `sys.Executor.SelectionStrategy = st` 是策略实验的核心开关（`StrategyExperiment:203`），仍可写 |
| `Workshop.AddJar/AddLiquid/...` | 领域层意图方法，本就该公开 |

## 3. 等价性论证

1. **JSON 契约零改动**：`StateSerializer` 只是**读**这些成员（`.Select((w,i)=>...)`、`.TakeLast(10)`、`.Count`、`[i]`），
   只读视图与可变列表读出来的内容逐项相同；DTO 与 `[JsonPropertyName]` 未动。⇒ 契约快照仍应是 **165 行**。
2. **规则与执行零改动**：没有改任何命令、求解器、可行性、切换逻辑。
3. **唯一的行为增强（且是防御性的）**：
   - `ClearWorkshops()` 会同时清空主/从选择；
   - `SetMasterIndex/SetSlaveIndex` 对越界下标抛异常。
   两者在**旧的合法调用路径上结果完全相同**：改动前的测试脚本里 12 处装配全部是"先加工作台、再设 0/1（或 null）"，没有一个越界。
4. **`Reset()` 逐项对照**：旧实现 `Workshops.Clear(); Orders.Clear(); CurrentEvent=null; EventHistory.Clear();
   LiquidProductionRate=new(){酒=1,蜜=1}; FlowSettings=(3,2); AutoCheckEnabled=false; CurrentMaster=null; CurrentSlave=null;
   ProducerModule=new(); InitializeDefault();` ⇒ 新实现把前两步换成 `ClearWorkshops()/ClearOrders()`（多做了"清主从"，随后本来也要清），
   把速率字典由"换对象"改为"清空重填"（**内容相同**），其余逐字一致。终态完全等价。
