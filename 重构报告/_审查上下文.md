## 1. 项目是什么

`D:\codex\jar-system-dotnet` —— 「陶罐系统」(jar-system)。

- **定位**：规则驱动的资源调度**解谜内核** + 多宿主演示壳。项目本位是"类似加工中心 / 工艺规划系统"：
  **罐子 = 工件，液体 = 耗材，订单 = 图纸**，规则把资源加工成满足订单的状态。
- **主部分（.NET）**
  - `src/JarSystem.Core` —— 可移植类库，**零外部依赖**（只用 .NET BCL + System.Text.Json）
  - `src/JarSystem.Web` —— ASP.NET Core 宿主 + 裸 WebSocket（默认绑 `127.0.0.1:3457`）+ 原生 JS 前端
  - `test/` —— 三个测试工程（自写 runner、策略实验、xUnit 骨架）
- **次部分（Godot）**：`hosts/godot/Jar` —— 用 `ProjectReference` 引用核心库（**不是第二份实现**），
  8 个脚本 + 13 条 headless 自检；刻意**不进 `JarSystem.slnx`**。
- **已放弃**：GGF 框架宿主（工程在仓库外；`重构报告/00_从这里继续.md` §1.7 留档）。
- **唯一交接入口**：`重构报告/00_从这里继续.md`（先读它，再按需读其它）。

## 5. 已知问题清单（审查时可直接核实或深化，不必重复"发现")

- **约 17 条「注释 vs 代码」矛盾**，例如：`WorldOptionsJson` 注释声称非法键不会静默生效
  （实际**没有** `UnmappedMemberHandling`，拼错的键被静默丢弃）；`Workshop` 类注释声称只暴露只读视图；

- **`verify.bat` 只把快照 diff 写进 `diff.txt`，并不据此判 FAIL** ⇒ 快照漂移不会让门变红。
- **前端无人守门**：九步**完全不覆盖 JS**（`wwwroot/js/app.js`、`canvas.js`），没有 JS 语法检查。
- **32 处内联 `onclick`**（`index.html` 18 + `app.js` 14）未改事件委托。
