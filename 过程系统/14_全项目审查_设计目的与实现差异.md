## 2. 审查方法

对"设计目的 vs 实际实现"的差异，用**可复现的方式**逐条验（`rg` 查"声明是否被读取"），而不是凭印象：
凡文档/接口**声明**了一个语义，就去查它**是否真的被某处读取**。这次查出的三处偏离全部属于"声明了但没人读"。

## 3. 本轮发现并修复的差异（三处，全在过程系统内）

| # | 声明处 | 症状 | 修法与覆盖 |
|---|---|---|---|
| **D1** | `IRuleModifier.Window.From`（"区间起点"） | `Expire` 只判 `To` ⇒ **"从第 N 刻起生效"的修饰器会立刻生效** | `ModifierStack` 记 `_now`（每 tick 由 `Expire` 刷新）+ `IsLive(m)` 参与全部查询；授予形状缓存也按 tick 失效。**S31 扩了断言**（`from=3` 在第 2 刻不生效、第 3 刻生效） |
| **D2** | `ProcessDefinition.Priority`（"同 tick 内推进顺序"） | 推进按字典插入顺序，**Priority 从不被读** | `AdvanceActive` 先按 `(Priority, 创建序)` 排序再推进。语义就位；当前无第二个并发过程 ⇒ 无可观测差异（如实记录） |
| **D3** | `ProcessInstance.DeadlineTick`（"超时即失败"） | 只被投影给客户端，**不参与判定** | 管线每 tick 查时限（闭区间：`tick == deadline` 仍算及时）⇒ 超时走失败收尾；`StartOrder(index, deadlineTicks)` 暴露为宿主 API。**新增 S32** 覆盖 |

> 三个都属于"半成品接口"：字段/属性/参数齐备、文档也写了，但**行为没接上**。
> 这类差异用编译器查不出来（都是合法代码），只有"逐个问它有没有人读"才会暴露 ——
> 这也是本轮审查的主要产出。

## 4. 此前各轮已修的设计-实现差异（汇总，便于一处查阅）

| 轮次 | 差异 | 处置 |
|---|---|---|
| P1 | A 类计划步骤的阶段名写成 `master_path`（应为 `solver_path`） | 契约快照当场变红 ⇒ 修正（门抓到的） |
| P1 | 从台阶段漏传记账器("0 步"的过程) | 自检③ 抓到 ⇒ 补传 |
| P2b | `ProcessRun` 把 tick 捕获成常量 ⇒ 异步轨多步记成同一个 tick | 改为提交时读时钟（实测抓到） |
| P2c | 契约里带浮点漂移（`0.8999999999999999` 等 7 处）+ 潜在少产一罐 | 定点化 + **有意重建基线**；策略实验数值位移 0.1–0.2pp 为证 |
| P3a | 守卫可能在过程"未开始"时判阻断（`Ready → Blocked` 非法） | `NoteBlocked` 先 `EnsureStarted`（S29 抓到） |
| P3b | "形状抑制"被保守地判为未判定 | 升级为精确判定（受限池重跑）+ `MODDIFF` 加判据 |
| P4b | 协议守卫的载荷键只扫 `CommandDispatcher` ⇒ 新文件的消息判 NOT-FOUND | 扫描源扩展到 `ProcessObserver`；提取调用改传全部源 |
| P4c | 两个命名空间成环（`Process↔Services`、`Process↔Executor`） | 端口/抽象拆环（依赖自检四项全空） |
| P4d | `Rules` 住在 `Process` 下 ⇒ `Domain → Process` 错层 | 独立成层 |
| P5 | 场景端点：路径按服务当前目录解析；元组返回被序列化成 `{}`；保存目标"找已存在文件"⇒ 500 | 三处修掉（冒烟实测抓到） |

**结论**：差异的发现者几乎全是"机器门 + 冒烟"，而不是人工阅读 —— 这说明本项目的门阵在起真作用；
本轮三处（D1–D3）是"人工按语义逐条查"才找到的，说明**语义覆盖率**这一类检查还需要人来做（或需要新的门）。

## 6. 建议（按价值/成本排序）

1. **把"声明是否被读取"机械化一部分**：本轮 D1–D3 的共性是"接口有字段、没人读"。
   可加一个轻量检查：对 `ProcessDefinition` / `IRuleModifier` / `ProcessInstance` 的公开属性，
   在测试里断言"每个字段至少在一个用例里被读到/影响到行为"（反射 + 行为断言，成本可控）。
2. **场景热重载**要先回答"运行中的世界怎么换规则"（玩法决策），不必急着做。
3. **A9/A10** 等存档需求出现时一起做（那时会有第二个使用者，抽象才有依据）。
